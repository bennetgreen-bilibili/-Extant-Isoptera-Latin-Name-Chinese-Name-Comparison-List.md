# 开放图片图集与图片页：授权与署名说明

本文件说明「开放图片图集」（species photo gallery）与「全部图片页」（/photos/）的图片来源、
许可策略、署名规则、页面结构与更新方式。

适用范围：`_data/species_photos.json`、`_data/photo_taxa.json`、
`_includes/photo-card.html`、`_includes/species-gallery.html`、`_includes/taxon-photos.html`、
`_layouts/photos.html`、`assets/gallery.css`、`assets/gallery.js`、`assets/vendor/photoswipe/`，
以及生成脚本 `.github/workflows/build_species_photos.py` 与
`.github/workflows/build_photo_pages.py`。

最后核对日期：2026-10-30（PhotoSwipe 5.4.4；许可白名单 policy version 2；
照片集合 photo set version 2——取消每物种 6 张上限，改为「有多少抓多少」）。

---

## 一、一句话原则

**只收录 CC0 / CC BY / CC BY-SA / 公有领域（Public domain）四种状态的照片**，逐条写明
「作者 · 许可 · 来源页」，图片**不外链转载、也不下载重传**，而是直接热链到 iNaturalist 与
Wikimedia Commons 的原图，版权始终留在摄影师手里（公有领域同理——只是版权已过期、
或权利人已明确放弃）。

翻页与「全部图片页」只改变**展示**方式，不改变许可判定：能进 /photos/ 的图，和能进物种页
前六张的图，走的是同一条白名单。

## 二、数据来源

| 来源 | 接口 | 每物种请求 | 关键参数 |
|---|---|---|---|
| iNaturalist | `https://api.inaturalist.org/v1/observations` | 1～3 次（翻页） | `taxon_name=<拉丁名>`、`photos=true`、`quality_grade=research`、`per_page=100`、`page=<n>`、`photo_license=cc0,cc-by,cc-by-sa` |
| Wikimedia Commons | `https://commons.wikimedia.org/w/api.php` | 1～4 次（续页） | `action=query`、`generator=search`、`gsrsearch="<拉丁名>"`、`gsrnamespace=6`、`gsrlimit=50`、`gsroffset=<n>`、`prop=imageinfo`、`iiprop=url\|extmetadata\|size`、`iiurlwidth=800`、`format=json` |

翻页都在多抓不到新合格照片时提前收手：iNaturalist 遇到短页（`len(results) < per_page`）
或候选已达 `MAX_PHOTOS * 3` 就停；Commons 跟随 `continue.gsroffset`，取满上限或候选够用即停。

### iNaturalist 的过滤链

1. `photo_license` 只让「至少有一张自由许可照片」的观察记录返回；
2. **观察记录的 `taxon.name` 必须与本站拉丁名完全相同**（大小写与三名词一致），
   因此搜索结果里冒出来的亚种、同属其他种、上级分类单元一律丢掉；
3. 逐张照片再查 `license_code` ∈ {`cc0`, `cc-by`, `cc-by-sa`}——一条观察里常混着
   「保留所有权利」的照片，只取自由许可的那几张；**iNaturalist 没有独立的公有领域标记**，
   `cc0` 就是它的公有领域选项（已收录）；
4. 缩略图用 `square` → `medium`（最长边 500px），灯箱图用 `square` → `large`
   （最长边 1024px，iNat 的 `large` 就是 1024 上限，已按原图长宽比换算 `data-pswp-width/height`）；
5. 署名直接用 `photo.attribution`（iNat 的标准格式，如 `(c) NoahM, some rights reserved (CC BY)`）；
   CC0 照片的 `attribution` 只有 `no rights reserved`，没有作者名，此时改用观察者账号
   （`iNaturalist observer <login>`），礼貌上也应当知道图是谁拍的；
6. 单条观察最多取 2 张（同一人连拍的一组近景会挤满整个网格），观察之间按最新（`-obs_id`）
   优先累计；**不再有「补足到 6 张就停」的上限**，会一直翻页抓到没有新的合格照片或触到
   `MAX_PHOTOS = 120` 的安全上限（sanity ceiling，仅防单物种病态膨胀，不是产品限制）。

### Wikimedia Commons 的过滤链

1. 文件名扩展名必须是 `.jpg/.jpeg/.png/.gif/.webp`（PDF、SVG 标志、DjVu 扫描件进不了灯箱）；
2. 许可名取 `extmetadata.LicenseShortName`，缺失时依次回退 `License`、`UsageTerms`，
   必须匹配下列之一（大小写不敏感）：
   - `CC0` / `CC0 1.0`
   - `CC BY x.y` / `CC BY-SA x.y`（允许 `CC BY-SA 3.0 de` 这类辖区版本后缀）
   - **公有领域**：`Public domain`、`No known copyright restrictions`、裸代码 `pd` / `pdm`，
     以及 Commons 的 PD 模板 `PD-old-70`、`PD-USGov`、`PD-self`、`PD-1996` 等（锚定 `PD-…`）
   - NC / ND / GFDL / 未知一律先被拒绝；
3. **公有领域的元数据矛盾就不收**：若公开域文件同时标着 `Copyrighted: true`，整张丢弃
   （宁缺勿错）；`LicenseUrl` 为空时统一指向
   `https://creativecommons.org/publicdomain/mark/1.0/`（Public Domain Mark，说明其「无已知版权限制」）；
4. Commons 的 `gsrsearch` 是**全文检索**，只靠许可还不够：文件名 / `ImageDescription` /
   `Categories` 中必须出现该拉丁名（亚种用前两个词，即双名）才算命中，避免把
   「白蚁后」这种泛泛的图挂到某个具体种名下；
5. 署名取 `Artist`，缺失时回退 `Credit`，仍缺失时写 `Wikimedia Commons`；**公有领域且
   完全没有作者信息**的写成 `Wikimedia Commons (public domain; author not stated)`，
   如实说明「作者未注明」，**不编造、不猜测**（超过 160 字截断）；
6. 许可链接取 `extmetadata.LicenseUrl`，缺失时按许可名拼 `https://creativecommons.org/…`，
   仍拼不出来就**整张丢弃**（宁缺勿错）；
7. 链接里的 `?utm_source=…` 追踪参数一律剥掉，保证 `src`/`thumb` 稳定可缓存。

## 三、许可白名单：收录什么、排除什么

| 许可 | 是否收录 | 原因 |
|---|---|---|
| CC0 1.0 | ✅ | 放弃版权，最自由；仍注明作者与来源（学术礼貌 + 便于溯源） |
| CC BY x.y | ✅ | 只需署名；本站按「作者 · 许可 · 来源链接」逐图署名 |
| CC BY-SA x.y | ✅ | 署名 + 相同方式共享。站内只**热链原图**、不复制文件，因此不产生衍生作品；若日后要下载转存，衍生部分须按同许可发布 |
| CC BY-NC* | ❌ | 禁止商业使用。本站目前非商业，但名录以 CC BY 4.0 发布、允许他人再利用（含商业场景），NC 图片会让整个页面的再利用边界变得不可判定 |
| CC BY-ND* | ❌ | 禁止演绎。图集要做缩略图裁剪（`object-fit: cover`）与灯箱展示，涉及尺寸/裁切层面的改动，ND 条款下风险过高 |
| 公有领域（Public domain / PD-…） | ✅ | 版权已过期或权利人明确放弃，比 CC BY 更宽松、可任意使用。**唯一风险是署名可靠性**（Commons 上大量 PD 文件没有作者信息），因此本站如实呈现：`Artist`/`Credit` 有就写，没有就写 `Wikimedia Commons (public domain; author not stated)`，许可一栏写 `Public domain` 并链接到 Public Domain Mark，来源页始终保留；`Copyrighted: true` 这种自相矛盾的文件不入库。原有科级插图的版权核查另见 `_tools/图片版权核查与处理清单.md` |
| GFDL / GFDL 双许可 | ❌ | 条款复杂（文档级传染、需附全文），与本站 CC BY 4.0 的数据许可不兼容，易误导复用者 |
| 许可未知 / 无声明 | ❌ | 默认版权保留，不能用 |

判定代码集中在 `build_species_photos.py` 的 `INAT_ALLOWED`、`COMMONS_CC0_RE`、
`COMMONS_CC_BY_RE`、`COMMONS_PD_RE`、`COMMONS_DENY_RE`；`--check` 会按同一套白名单复核
已提交的 JSON。白名单或判定规则一改，就把 `LICENSE_POLICY_VERSION` 加一，
数据文件里的 `meta.license_policy_version` 会跟着记下这一轮是用哪版规则抓的。

**与抓取上限无关的另一枚版本号**：`PHOTO_SET_VERSION` 记录「每物种照片集合的形态规则」
（当前 2 = 取消 6 张上限、双源分页）。它和许可版本号各管各的：放宽许可要重扫全量，
改动集合规则只需把旧条目按新规则重抓一次。两者的差别见第六节。

## 四、署名规则（站内呈现）

每张图的卡片集中在 `_includes/photo-card.html`（物种页图集、分类单元页图片小节、
/photos/ 图片页三条路径共用同一个卡片，署名因此永远一致），输出：

```html
<figure class="gallery-card">
  <a class="gallery-item" href="<原图>" data-pswp-width data-pswp-height
     data-credit="作者" data-license="CC BY 4.0"
     data-license-url="https://creativecommons.org/licenses/by/4.0/"
     data-source-page="https://www.inaturalist.org/observations/…">
    <img src="<缩略图>" alt="<拉丁名> <中文名>（作者，许可）" loading="lazy">
    <span class="gallery-item-zoom">⤢</span>
  </a>
  <figcaption class="gallery-caption">
    <span class="gallery-caption-credit">作者</span>
    <span class="gallery-caption-meta"><a href="<CC 许可链接>">许可</a><a href="<来源页>">iNaturalist</a></span>
  </figcaption>
</figure>
```

- 版式为**瀑布流**：`assets/gallery.css` 用 CSS 多列（`column-width` + `break-inside: avoid`）分列，
  每张图按原始宽高比显示、不裁切，各列高度自然错落；1 张 / 2 张照片时自动收窄列数，避免右侧大片空白；
- 每张图**下方常显图注**：`作者 · 许可（链接到 CC 许可全文） · 来源（链接到原始页面）`，
  桌面、触屏、禁用 JS 时都可见，不依赖悬停；
- PhotoSwipe 灯箱底部重复同一行署名，由 `assets/gallery.js` 从 `data-*` 读取、用
  `textContent` 写入（不拼 HTML，避免图注里的尖括号/引号造成注入）；
- 脚本未加载或用户禁用 JS 时，点击图片直接在新标签页打开原图，图注仍然可见；
- **转载本站图集的人**：请保留「作者 · 许可 · 来源页」三项，并保留 CC 许可链接；
  图片本身仍受原作者许可约束，不因出现在本站而改变。

## 五、三种图集形态与 `/photos/` 图片页

同一个物种的照片集合，在三处呈现，截断只发生在展示层（`limit` 参数），数据层只有一份：

| 位置 | 内容 | 出处 |
|---|---|---|
| 物种页 `/species/<slug>/` | 前 6 张 + 「查看全部 N 张 →」 | `_includes/species-gallery.html`（`sg_limit = 6`） |
| 科 / 亚科 / 属页 | 跨种扁平预览 6 张 + 「查看全部 N 张 →」 | `_includes/taxon-photos.html`（`limit=6`、`more="1"`） |
| `/photos/` 图片页 | 物种页：该种**全部**照片；分类单元页：按种分组，每种 6 张 + 「该种全部 N 张 →」 | `_layouts/photos.html` + `_includes/taxon-photos.html`（`grouped="1"`） |

- 物种图片页 `/species/<slug>/photos/`：渲染 `site.data.species_photos.species[page.photo_latin]`
  的**全部**照片（唯一不做截断的地方）。
- 分类单元图片页 `/<rank>/<id>/photos/`（`rank` = genus / subfamily / family）：
  按种分组，每组一个小标题（链接回该种页面）+ 计数 + 最多 6 张 + 「该种全部 N 张 →」。
  分组模式里每个分组各自带一个 `.species-gallery` 容器，而父容器不带——PhotoSwipe 以
  `.species-gallery` 为 gallery 单元，这样既能让每组独立成册，也不会把父级与子级重复收集。
- 之所以不给分类单元图片页铺全量：白蚁科（Termitidae）单科就有 1918 张照片、106 个物种，
  一次渲染会把页面拖垮。分组 + 每组 6 张 + `loading="lazy"` 是刻意的取舍。
- 数据文件 `_data/photo_taxa.json` 是「哪些分类单元有图」的索引（`species` / `genus` /
  `subfamily` / `family` 四个映射，值含照片数、物种数与图片页 URL），由
  `build_photo_pages.py` 产出，`build_taxonomy_pages.py` 读它决定是否给该类元页加
  `has_photos: true` 与图片小节。**生成顺序不能颠倒**：先 `build_photo_pages.py`，
  再 `build_taxonomy_pages.py`。
- `/photos/` 页面在 `default.html` 里带 `data-pagefind-ignore`：纯图集不进站内搜索索引，
  否则搜索「白蚁」会被三百多个「全部图片」页挤满。

## 六、如何更新数据

脚本只用 Python 标准库，行为确定（同样的输入产出同样的 JSON；`meta.generated`
只在内容变化时刷新），可直接在 CI 里 `--check`。

```powershell
# 只校验已提交的 JSON（schema、许可白名单、计数、重复项）；违规时退出码 1
python .github/workflows/build_species_photos.py --check

# 先小规模验证（12 个代表种），确认接口与许可解析正常
python .github/workflows/build_species_photos.py --write --all-names _tmp/probe_names.txt

# 全覆盖：默认从已提交的缓存续跑，只查还缺的物种
python .github/workflows/build_species_photos.py --write --workers 4 --budget 5400 --checkpoint 200

# 只补 iNaturalist（Commons 已查过的不再请求）
python .github/workflows/build_species_photos.py --write --only inat

# 强制重查（忽略缓存，结果覆盖旧条目）
# 许可白名单变化后（例如新增公有领域）必须跑一次，否则负缓存里的物种不会再被查
python .github/workflows/build_species_photos.py --write --refresh --only commons

# 循环补抓：每轮有界、轮间自动休息，直到没有待抓物种（本地/CI 通用）
python .github/workflows/crawl_species_photos_loop.py --round-budget 900 --max-rounds 4

# 重新生成 /photos/ 图片页与 _data/photo_taxa.json（必须先于分类单元页生成器）
python .github/workflows/build_photo_pages.py
python .github/workflows/build_photo_pages.py --check
```

**断点续跑**：`_data/species_photos.json` 本身就是缓存。
`meta.no_photos.inaturalist` / `meta.no_photos.commons` 记录「查过但没有合格照片」的物种，
因此重跑不会重复请求；由 `--budget` 或 `--limit` 中断后，**重复同一条命令即可继续**，
每 `--checkpoint` 个物种落盘一次（默认 250）。中断后最省事的续跑命令：

```powershell
python .github/workflows/build_species_photos.py --write --workers 4 --budget 5400
```

**照片集合版本迁移（`meta.photo_set_version`）**：数据文件顶部记着「这批条目是用哪版
集合规则抓的」。单次运行只处理本轮的待办，**迁移不会在一轮里悄悄完成**——只要还有条目
的版本号低于 `PHOTO_SET_VERSION`，脚本就在 stderr 打出
`photo-set migration still open: meta.photo_set_version stays at 1, rerun to keep lifting the old ceiling`，
并把文件里的版本号继续留在旧值。要完成迁移，把同一条命令再跑一次即可（`plan_pending()` 只挑
旧版本条目与尚未查过的物种）；等 stderr 不再出现这行提示，版本号才会升到 2，
`--check` 也才认为数据是最新的。
迁移期间**不要**跑 `build_photo_pages.py --check` 判失败就以为页面生成坏了——张数还在变，
图片页本来就会随之变化，对齐要在迁移收尾之后做。

其他参数：`--limit N` 本次最多处理 N 个物种；`--budget SECONDS` 时间预算（0 = 不限）；
`--refresh` 忽略缓存；`--only inat|commons` 单源；`--all-names FILE` 用外部名单
（每行一个拉丁名，`#` 开头为注释）；`--workers N` 并发抓取（默认 3，仍未超过
iNat 60 次/分、Commons 串行请求的礼貌上限）；`--checkpoint N` 落盘间隔。

**负缓存**：`meta.no_photos` 里的物种视为「查过、当时没有合格照片」，普通续跑不会再请求它们
（这正是覆盖率补完之后重跑很快的原因）。只有 `--refresh` 才会重查负缓存里的物种。
注意集合规则升级**不会**自动重查负缓存：负缓存记录的是「这个源没有合格照片」，
与「以前只留 6 张」无关；若怀疑某个源其实有图只是当时漏了，用 `--refresh --only <source>`。

### 循环爬取与线上自动化

| 文件 | 作用 |
|---|---|
| `build_species_photos.py` | 单轮抓取器；一次运行处理若干物种，`_data/species_photos.json` 即缓存与断点 |
| `crawl_species_photos_loop.py` | 循环调用单轮抓取器：每轮 `--round-budget` 限时、轮间 `--sleep`；连续 `--max-idle-rounds` 轮没有进度就自动停下（API 故障时空转保护）；`--refresh` 会强制只跑一轮 |
| `build_photo_pages.py` | 由 `species_photos.json` 派生 `/photos/` 页面与 `_data/photo_taxa.json`；`--check` 校验产物是否过期 |
| `species_photos_crawl.yml` | GitHub Actions：每天 03:17 UTC 定时 + 手动触发；跑完 `--check`、提交缓存，再显式派发 `pages.yml` 重新部署 |

工作流手动触发时的输入：

- `rounds`：最多跑几轮（`0` = 一直跑到没有待抓物种）；
- `round-budget`：每轮时间预算（秒）；
- `only`：只抓 `inat` 或 `commons`；
- `rescan-licenses`：忽略缓存重扫许可。**新增/放宽白名单后勾一次**（Commons 全量约 20 分钟），
  否则负缓存里的旧物种不会重新查询；不填 `only` 时默认只重扫 Commons（公有领域只影响它），
  勾上后 `rounds` / `round-budget` 不生效，会一次跑完。

两个平台限制，写在这里免得以后困惑：GitHub 定时工作流在仓库连续 60 天无提交时会被自动停用；
用 `GITHUB_TOKEN` 推送的提交不会触发其它工作流，所以工作流最后要显式 `gh workflow run pages.yml`。

礼貌爬取：UA 带项目地址；iNat 请求起步间隔 1.05s（≈57 次/分），Commons 0.34s；
遇到 429 / 5xx 指数退避（4s→8s→16s→32s，尊重 `Retry-After`），重试 4 次仍失败就跳过该物种、
下次再查（**不会**把失败写成「没有照片」）。翻页在同一个礼貌客户端里排队，
并发只影响「同时有几个物种在抓」，不会突破单源的最小请求间隔。

不使用 CDN 运行时依赖：文件已 vendored 进仓库，离线/被墙也能用；升级时按上表整目录替换即可。
`assets/gallery.js` 是纯 ES5 IIFE，不依赖模块加载器；**只有页面存在 `.species-gallery`
时才启动**，并且用 IntersectionObserver / 首次交互（pointerdown、touchstart、keydown、focusin）
延迟初始化，不拖累首屏。PhotoSwipe 未加载时脚本静默退出，图集退化为普通图片链接。

灯箱按 `.species-gallery` 这个**容器**装配，一次装配只跑一遍（单例），
图注从当前 slide 的 `data.element` 上现读 `data-credit` 等属性——所以同一页里存在多个图集
（例如分类单元图片页按种分组）时，图注不会串到别的物种上。

### 接入

`_layouts/species.html` 在 `{{ content }}` 之后、分页脚之前插入：

```liquid
{% include species-gallery.html %}
```

`_layouts/default.html` 的 `</head>` 前加样式（顺序：PhotoSwipe 在前，站点覆盖在后），
`</body>` 前加脚本（`defer` 与站内其他脚本互不影响）：

```liquid
<link rel="stylesheet" href="{{ site.base_url }}/assets/vendor/photoswipe/photoswipe.css">
<link rel="stylesheet" href="{{ site.base_url }}/assets/gallery.css">
<script src="{{ site.base_url }}/assets/vendor/photoswipe/photoswipe.umd.min.js" defer></script>
<script src="{{ site.base_url }}/assets/vendor/photoswipe/photoswipe-lightbox.umd.min.js" defer></script>
<script src="{{ site.base_url }}/assets/gallery.js" defer></script>
```

这五行是**条件加载**的，条件是：

```liquid
{% if page.collection == 'species' or page.photo_kind or page.has_photos %}
```

即「物种页 / `/photos/` 图片页 / 带图片小节的分类单元页」三者之一才加载。
`page.has_photos` 由 `build_taxonomy_pages.py` 写进 front matter（依据 `_data/photo_taxa.json`），
`page.photo_kind` 由 `build_photo_pages.py` 写进图片页 front matter；
没有图的页面不会白白下载 76 KB 的灯箱。

## 八、热链（hotlink）说明

- 图集**只存 URL**，不下载、不转存、不在仓库里分发图片文件；`<img src>` 与灯箱原图都直接指向
  `inaturalist-open-data.s3.amazonaws.com` / `static.inaturalist.org` / `upload.wikimedia.org`。
- 好处：不会误传「已获授权」的错误印象，图片更新自动跟随源站，仓库体积不膨胀。
- 代价：**源站改路径、删图、限流时会显示裂图**。处理办法：
  1. 单张失效：直接改 `_data/species_photos.json` 里该条的 `src`/`thumb`（或整条删掉），
     然后 `--check`；下一次 `--refresh` 会自动重建该物种的条目；
  2. 大面积失效（源站换域名/加 referer 限制）：先跑 `--check` 看还有多少条，
     再 `--write --refresh --only inat`（或 `--only commons`）重建；
  3. 某个物种的图确实被删了：从 `species` 里删掉该物种键，并把拉丁名加进
     `meta.no_photos` 对应数组（保持有序），免得下次又被反复查询。
- 灯箱与 `<img>` 都带 `loading="lazy"`、`decoding="async"`，缩略图仅最长边 500px（iNat）
  或 800px 宽（Commons）。**单页渲染有上限**：物种页 6 张；分类单元页扁平 6 张；
  分类单元图片页按种分组、每组 6 张；只有物种图片页会渲染该种全量（常见种可达数十上百张，
  但全部懒加载）。
- Commons 的 `src` 用的是**原图**（部分可达数 MB）。若日后觉得太慢，把脚本里
  `src = info["url"]` 改为 `thumburl` 的 1600px 版本即可，属于一行改动。

## 九、已知局限与风险

1. **识别正确性**：iNat 只取 research grade 且分类单元精确相等的观察，仍可能有误鉴定；
   Commons 靠「拉丁名出现在文件名/描述/分类」+ 许可白名单，无法保证图中就是该种，
   尤其是形态相近的小型白蚁。**图集是辅助，不是分类学证据。**
2. **覆盖不均**：常见种能攒到几十上百张（全站当前最多 120 张，即 `MAX_PHOTOS` 安全阀）；
   汇总层面 `Nasutitermes` 378 张 / 13 种、`Macrotermes` 320 张 / 13 种、白蚁科 `Termitidae`
   1918 张 / 106 种，而大量冷门种一张都没有——没有合格许可照片时**不生成条目**，
   绝不填充占位图或他人版权图。页面上的「N 张」永远是实际抓到的自由许可照片数。
3. **许可版本**：iNat 的 `license_code` 不含版本号，署名行与许可链接统一指向 CC 4.0 版本
   （iNat 站点自身即按 4.0 呈现）；Commons 保留 `LicenseShortName` 原样（如 `CC BY-SA 3.0`）。
4. **CC0 署名**：CC0 法律上不要求署名，本站仍写观察者账号，属于礼节而非义务。
5. **公有领域的署名**：PD 不要求署名，但很多 PD 文件**确实没有作者信息**（Commons 老图书插图常见）。
   本站的写法是如实呈现而不是猜测：有 `Artist`/`Credit` 就写，没有就写
   `Wikimedia Commons (public domain; author not stated)`，许可写 `Public domain` 并指向
   Public Domain Mark，来源页链接始终保留——读者可以自己回溯核对。**不要**为了「看起来完整」
   而给 PD 图补一个作者；宁可写「未注明」。
6. **速率**：iNat 未认证 60 次/分。取消 6 张上限后单物种请求数从 1 次涨到最多 3 次（iNat）
   与 4 次（Commons），全量首轮跑完要更久；中断属于正常情况，按第六节续跑即可。
7. **数据文件体积**：`_data/species_photos.json` 含全部已查物种的负缓存（`meta.no_photos`），
   是 Jekyll 每次构建都会解析的静态数据；取消上限后照片条目变多（当前约 2 MB 量级），
   仍可接受；若将来膨胀到数 MB，可把负缓存挪到单独的 `_tmp/` 侧车文件（不进仓库）。
   `.github/workflows/build_species_photos.py` 里 `MAX_PHOTOS = 120` 是防止单物种病态膨胀的
   安全阀，若要真正「无上限」，改这一个常量即可，但请同步本节与第六节的版本说明。
