# 外部权威库外链与一致性核对（GBIF / Catalogue of Life / Wikidata / Blattodea Species File）

本页说明站点「其他数据库」区块、一致性提示与 JSON-LD `sameAs` 的数据来源、生成方式、判定规则、刷新流程与限制。
**原则：外部库只用于外链与对照提示，绝不写入/改写站内名录数据。**

## 1. 一句话概览

| 项目 | 内容 |
|---|---|
| 数据文件 | `_data/authority_links.json`（GBIF + COL + Wikidata 缓存）、`_data/bsf_links.json`（世界名录对照缓存） |
| 生成脚本 | `.github/workflows/build_authority_links.py`、`.github/workflows/build_bsf_links.py` |
| 展示位置 | 物种页「其他数据库」区块（`_includes/species-authority.html`）；物种页 JSON-LD（`_includes/species-jsonld.html`）；`/data/` 页「外部权威库对照」；`downloads/isoptera-authority-crossref.csv` |
| 抓取方式 | 构建时增量刷新（CI 中 `--write --refresh --budget …`），完整缓存随仓库提交 |
| 是否需要 key | 否。四个数据源都免费公开，无需注册 |
| 改动站内数据 | 不会。脚本只读 `_species/*.md`，只写缓存与 CSV |

## 2. 数据源与许可

### 2.1 GBIF Backbone Taxonomy
- 接口：`GET https://api.gbif.org/v1/species/match?name=<学名>&kingdom=Animalia`
- 取用字段：`usageKey`、`scientificName`、`canonicalName`、`rank`、`status`（ACCEPTED / SYNONYM / DOUBTFUL）、`confidence`、`matchType`、`acceptedUsageKey`；异名时再查 `GET /v1/species/{acceptedUsageKey}` 取接受名。
- 链接：`https://www.gbif.org/species/<usageKey>`
- 许可：GBIF Backbone 元数据 CC BY 4.0，使用时须署名 GBIF（站点已在数据页与区块脚注署名）。
- 免费、无 key；礼貌请求（全局限速 6 req/s、8 并发、指数退避）。

### 2.2 Catalogue of Life（ChecklistBank）
- 接口：`GET https://api.checklistbank.org/dataset/3LR/match/nameusage?q=<学名>`
- 取用字段：`usage.id`、`usage.status`、`usage.label`、`usage.rank`、`usage.classification[0]`（异名时的接受名）；`type`（exact / variant / none）。
- 链接：`https://www.checklistbank.org/dataset/3LR/taxon/<id>`
- 版本：数据集别名 `3LR` 指向当前 COL 年度发布（缓存里记录实际 dataset key、DOI、日期；示例：key 316595，doi 10.48580/dgzh4）。换版时改 `_config.yml` 的 `external.col_taxon` 与脚本常量 `COL_DATASET`。
- 免费、无 key。

### 2.3 Wikidata
- 接口：`https://query.wikidata.org/sparql`，按 **P225（分类单元学名）** 精确匹配，一批 120 个学名一次查询，失败自动二分重试。
- 链接：`https://www.wikidata.org/wiki/<QID>`
- 许可：CC0 1.0。

### 2.4 Blattodea Species File（世界名录，含原 Isoptera Species File）
- 站点：`https://cockroach.speciesfile.org`（TaxonWorks / TaxonPages，MIT 开源；无稳定公开 API，见第 5 节）。
- 只用于物种页外链与人工核对工作表，不参与一致性判定。

### 2.5 判定规则（为什么有些名没有外链）
- **GBIF 外链门槛**：`matchType` 为 `EXACT`，或为 `FUZZY` 且 `confidence ≥ 95`；且返回阶元必须是 `SPECIES` / `SUBSPECIES`。属级、科级或低置信度的模糊结果一律不给链接（否则会把「属级近似」误当成本种）。
- **COL 外链**：只要 ChecklistBank 返回了 name usage 记录就给链接，并标注 accepted / synonym。
- **一致性提示**：见第 4 节的标记表。

## 3. 生成与刷新

```bash
# 只统计（不写文件）：查看还差多少条
python .github/workflows/build_authority_links.py

# 增量抓取并写入缓存 + CSV（默认只补缺）
python .github/workflows/build_authority_links.py --write

# 定时/手动刷新：重抓 30 天前的条目，最多花 10 分钟
python .github/workflows/build_authority_links.py --write --refresh --stale-days 30 --budget 600

# 全部重抓（换 COL 年度版本后建议执行）
python .github/workflows/build_authority_links.py --write --refresh-all

# 校验已提交缓存（CI 用，不联网）
python .github/workflows/build_authority_links.py --check

# 统计报告
python .github/workflows/build_authority_links.py --report
```

- 抓取 3068 个学名 × 2 个接口 ≈ 6100 次请求，约 20 分钟（8 并发、6 req/s）。中断后重跑自动续传。
- 每个条目的 `_d` 字段记录抓取日期，`--refresh --stale-days N` 只重抓过期条目。
- CI（`.github/workflows/pages.yml`）在 Jekyll 构建前执行一次有限预算的刷新（`--budget 120`），因此部署版会比仓库缓存略新；仓库缓存本身由维护者定期 `--write` 后提交。

## 4. 一致性标记（flags）

缓存里每个学名有 `flags` 数组，物种页据此显示提示；CSV 里的 `consistency` 列给出中文说明。

| flag | 含义 | 页面表现 |
|---|---|---|
| （空） | 与 GBIF、COL 的接受名一致 | ✔ 绿色「与接受名一致」 |
| `gbif_synonym` | GBIF 把本站名处理为异名 | 黄色冲突块，给出 GBIF 接受名与链接 |
| `col_synonym` | COL 把本站名处理为异名 | 同上（COL 接受名） |
| `gbif_doubtful` | GBIF 标记 DOUBTFUL | 黄色提示 |
| `gbif_fuzzy` | GBIF 仅模糊匹配（未达外链门槛） | 黄色提示 |
| `gbif_missing` / `col_missing` | 对应库未收录 | 黄色提示 |
| `gbif_rank_mismatch` / `col_rank_mismatch` | 外部库阶元与本站记录不同 | 黄色提示 |

重要说明：
- 本站采用 Engel 等（2024）体系与原始文献的处理（例如 Heterotermitidae 与部分传统 Rhinotermitidae 的归属），而 GBIF Backbone 的分类更新有滞后，因此**分类级别（科/亚科）差异不写入站内数据**，也不做自动「纠正」。
- 异名提示仅表示「外部库把该名视为异名」，不代表本站错误：本站可能有意采用该名为有效名。是否修订由人工判断，依据见各物种页的模式产地、次异名与文献。
- 提示文案中的「本站数据未改动」是硬性约定：脚本没有写 `_species/` 的代码路径。

### 4.1 名称差异逐对归并（关系 · 方向 · 接收名）

「外部库把本站名当异名」这句话不能照抄：本站名可能本身就是有效名，外部库（尤其 GBIF 的属级并系处理）
只是把它并进了旧属。所以看板把 12 条名称差异整理成 **12 对「本站名 ↔ 外部库主张的接受名」**
（同一对在多个库出现只算一次），逐对判定：

- **关系 `relation`**：属相同或加词不同 → `synonym`（真异名）；加词相同、属不同 → `combination`（同种异属，
  只是组合不同，**不算异名**）。当前 1 对异名、11 对组合差异。
- **方向 `direction`**：逐库按**物种级**结论投票（仅匹配到属/科、模糊匹配、未收录都不投票）。
  真异名：没有任何库说本站名是接受名 → `external`（外部接受名为接收名）；
  组合差异：多数库采用本站名 → `site`（**本站名为接收名**），否则 `disputed`（方向待定）。
  当前 0 / 6 / 6 对；另有 `disputed: true` 表示库间结论互相矛盾（8 对）。
- **可补录 `recordable`**：只有「真异名 + 外部库名为接收名 + **至少两个分类数据库一致认定**」才为真；
  GBIF Backbone 的相反结论（仍标 ACCEPTED）只作「方向有分歧」提示，不否决。当前 0 对。

数据与展示：

- `_data/name_issues.json`：`synonym_pairs`（每对含 our / external / relation / direction / votes /
  receiving / disputed / recordable / recorded）、`species_authority`（物种页索引：`incoming` 本种接收了哪些异名、
  `outgoing` 外部库把本名放在哪个名字下）、`synonym_of_slug`（已补录异名的反查）；
  `meta.counts` 里有 `conflict_pairs` / `pairs_relation_*` / `pairs_direction_*` / `pairs_recordable` / `pairs_recorded`。
- 页面：`/list/name-issues/#synonyms`（三语）逐对列出关系、方向、各库判定、补录状态；
  物种页「其他数据库」区块分 incoming（外部库归入本种的异名）/ outgoing（外部库把本名放在哪个名字下）两侧。
- 下载：`downloads/isoptera-synonym-pairs.csv`（15 列，一行一对，含关系、方向、接收名、补录状态）。

### 4.1.1 补录进站内数据的异名（authority_synonym_*）与正式合并

「记录到对应的接收名下面」分两层：逐对归并表只是提示；**补录**才是写进站内数据。规则是
「真异名 + 方向明确为外部库名为接收名 + **至少两个分类数据库一致认定**」，GBIF Backbone 对滞后组合仍标
ACCEPTED 时只作「方向有分歧」提示、不否决。

`authority_synonym_*` 只用于「异名另有独立记录、是否合并待定」的情形，落点是接受名物种页的 front matter：

```
authority_synonym_count: 1
authority_synonyms: "<异名学名> <命名人>, <年份>"          # 多个用 ; 分隔
authority_synonym_localities: "<模式产地>"                # 与异名逐条对齐
authority_synonym_sources: "gbif,col,bsf"                 # 同一异名的来源用 , 分隔
```

- `build_species_body.py` 据此在「## 次异名」一节末尾生成「### 依外部权威库补录的异名」小节；
  `build_search_index.py` 也解析这个项目符号列表，所以名录检索能按补录的异名命中接受名。
- `build_name_issues.py` 读这些字段判定 `recorded` / `pairs_recorded` / `synonym_of_slug`：
  看板标「已补录」。
- `_tools/check_site.py` 校验：`authority_synonym_*` 三个列表逐条对齐；对的 relation/direction/接收名、
  species_authority 索引、补录标记与计数、`synonym_of_slug` 互相自洽；`search-index.json` 能按补录异名命中。

**2026.10.30 版已把此前 3 对「已补录」异名正式合并**：异名物种页删除，三语名录、`isoptera-data.json`、
`data/` 结构化数据与归档数据集都不再单列；命名人与模式产地并入接受名的 `synonyms` / `synonym_localities`，
`synonym_count` 各加 1，`authority_synonym_*` 字段删除（因此看板当前 `pairs_recorded = 0`）：

- *Amitermes californicus* → *Amitermes wheeleri*（GBIF / CoL / BSF 一致）
- *Coptotermes guizhouensis* → *Coptotermes formosanus*（CoL / BSF 一致；GBIF 仍标接受名）
- *Nasutitermes dasyopsis* → *Nasutitermes nigriceps*（CoL / BSF 一致；GBIF 仍标接受名）

*Pericapritermes metatus* → *P. appellans metata* 只有 CoL 一库给结论，保持待核对、不补录。

### 4.2 链接基址与已知显示问题

`build_name_issues.py` 的链接基址读自 `_config.yml` 的 `external.*`，这些值后面带有 YAML 行尾注释
（例如 `gbif_species: "https://www.gbif.org/species"   # + /<GBIF usageKey>`）。脚本必须按 YAML 规则
先去注释再拼接，否则会生成 `https://www.gbif.org/species"  # + …/123` 这类坏 URL；页面上它会让
「外部记录 / 接受名」的链接点不动，还会提前闭合 `href` 引号、把后面的 HTML 变成转义文本。
`_tools/check_site.py` 现在会校验命名差异产物里没有带空白 / 引号 / `<` / `>` / `#` 的 URL。

### 4.3 拼写变体与人工核对备注（_data/name_issue_reviews.json）

外部库之间、外部库与原始描述之间，存在同一物种的**拼写变体**（少一个字母、改名性词尾等）。这类条目在「匹配存疑」里看起来像本站拼写有问题，实际常是外部库的写法差异；另有一种情况是 GBIF Backbone 尚未收录新名，模糊匹配落到了**另一个有效种**上。本名录以原始描述为准，**不改站名**，把核对结论写进看板备注。

- 数据文件：`_data/name_issue_reviews.json`。`reviews[]` 每条按 `latin` 匹配，可用 `source`（gbif / col / bsf）与 `kind`（fuzzy / ambiguous / higherrank / missing / synonym）限定到具体条目；`verified`（默认 true）让页面显示「已人工核对」，`note` 写进备注列并覆盖该条目的自动备注。
- 生效方式：`build_name_issues.py` 读取该文件，把 `verified` / `note` 写进 `_data/name_issues.json`、公开副本与 CSV；**不改 `_species`、不动两个外部库缓存，也不参与 `synonym_pairs` 的关系/方向判定**。有备注却没匹配到条目时脚本直接报错，避免备注悄悄失效。
- 与第 5 节 BSF 工作表的区别：工作表解决「本站名匹配到 BSF 的哪个 OTU」（写回 `_data/bsf_links.json` 的 `verified` / `notes`）；本文件解决「看板条目为什么可以判为已核对」，两者可以同时存在。

当前 4 条（2026-10-30 核对；结论均为本站名正确、外部库的写法或匹配有误）：

| 本站名 | 外部库写法 / 匹配结果 | 判定依据 |
|---|---|---|
| *Incisitermes mariae* Scheffrahn, 2024 | GBIF Backbone 未收录，模糊匹配到近缘种 *I. marianus* (Holmgren, 1912)（另一个有效种，**不是拼写变体**） | 原始描述 Scheffrahn, Austin & Szalanski, 2024（Zootaxa 5428: 427–439，模式产地 Trinidad and Tobago: Acono）；Catalogue of Life 与 BSF 均按本名收录 |
| *Cortaritermes silvestrii* (Holmgren, 1910) | GBIF Backbone / BSF 作 *silvestri*（单 i） | Termite Database 记录的原始组合 *Eutermes (Eutermes) silvestrii* Holmgren, 1910: 281–283；ION、CTFB（Catálogo Taxonômico da Fauna do Brasil）、NCBI 一致 |
| *Euhamitermes chhotanii* Maiti, 1983 | GBIF Backbone 作 *chhotannii*（双 n） | BSF、Catalogue of Life 与 ION 收录的 Maiti, 1983 原始描述记录均作 *chhotanii* |
| *Niuginitermes variratae* Roisin & Pasteels, 1996 | BSF / Catalogue of Life / GBIF 作 *variatae*（少一个 r） | 原始描述摘要（Roisin & Pasteels, 1996，Invertebrate Taxonomy 10(3): 507–616）明确作 *N. variratae*, sp. nov. |

新增一条备注：在 `reviews[]` 里加 `{"latin": "...", "source": "gbif", "kind": "fuzzy", "note": "人工核对：…"}`，再跑
`python .github/workflows/build_name_issues.py --write`；`--check` 会校验四个产物是否与生成结果一致。

## 5. 世界名录对照（Blattodea Species File）

BSF 已并入原 Isoptera Species File，覆盖蜚蠊与白蚁，提供命名、文献、模式标本、分布与图片。它由 TaxonPages / TaxonWorks 构建，**没有稳定公开 API**，所以采用「半自动」流程：

1. `build_bsf_links.py` 通过 BSF 页面所用的公开 TaxonWorks 接口按学名自动检索 OTU，生成 `_data/bsf_links.json`；
2. 同时导出人工核对工作表 `_tools/bsf对照/工作表.csv`（含自动匹配结果与待核对列）；
3. 人工核对后在表里把 `check_status` 改为 `已核对`，用 `--import` 合并回缓存，物种页才会显示「已人工核对」徽章；
4. 未核对的自动匹配条目显示「自动匹配」，未检索到的显示「未检索到」，匹配不确定的显示「匹配不确定，待人工核对」。

详见 `_tools/bsf对照/操作说明.md`。BSF 深链格式：`https://cockroach.speciesfile.org/otus/<OTU_ID>/overview`。

## 6. 结构化数据（JSON-LD）

物种页由 `_includes/species-jsonld.html` 输出 `@graph`：

- `Taxon`：`name`、`scientificName`（含命名人年份）、`taxonRank`、`alternateName`（中文正名）、`parentTaxon`、`sameAs`（GBIF / COL / Wikidata / BSF）、`identifier`（PropertyValue：GBIF usageKey、COL ID、Wikidata QID）、`url`、`isPartOf`（指向站点 Dataset 实体 `#dataset`）。
- `BreadcrumbList`：名录 → 科 →（亚科）→ 属 → 种/亚种，位置与页面面包屑一致。

首页（`index.md` / `en/index.md` / `es/index.md`）的 `Dataset` JSON-LD 已加固定 `@id`，三语页面与全部物种页共享同一实体 ID，形成 `Dataset ← isPartOf ← Taxon` 的实体图。JSON-LD 字段在数据缺失时自动省略（例如没有 Wikidata 条目时不输出对应 `sameAs`），不会输出空数组。

## 7. 已知限制

- 外部库更新滞后（尤其 GBIF Backbone 与 COL 对 2024 年后新组合、新亚科的收录），故「未收录」不等于名称无效。
- COL 年度发布换版后，旧 usage id 可能失效；脚本按学名重新匹配，链接会跟着更新。
- Wikidata 的 P225 只收录有独立条目的分类单元；冷门种通常没有 QID，属于正常情况。
- 仅按学名匹配，未使用模式标本、命名人消歧；同名异物（不同界）已通过 `kingdom=Animalia` 限制，但同名属/种异名关系仍可能出现，故异名提示需人工判断。
- 抓取日期与数据源版本都记录在 `_data/authority_links.json` 的 `meta` 中，物种页脚注显示抓取日期。
