# 外部权威库外链与一致性核对（GBIF / Catalogue of Life / Wikidata / Blattodea Species File）

本页说明站点「其他数据库」区块、一致性提示与 JSON-LD `sameAs` 的数据来源、生成方式、判定规则、刷新流程与限制。
**原则：外部库只用于外链与对照提示，绝不写入/改写站内名录数据。**

## 1. 一句话概览

| 项目 | 内容 |
|---|---|
| 数据文件 | `_data/authority_links.json`（GBIF + COL + Wikidata 缓存）、`_data/bsf_links.json`（世界名录对照缓存） |
| 生成脚本 | `.github/workflows/build_authority_links.py`、`.github/workflows/build_bsf_links.py` |
| 展示位置 | 物种页「其他数据库」区块（`_includes/species-authority.html`）；物种页 JSON-LD（`_includes/species-jsonld.html`）；`/data/` 页「外部权威库对照」；`downloads/isoptera-authority-crossref.csv` |
| 抓取方式 | 构建时增量刷新（CI 中 `--write --refresh --budget …`），完整缓存随仓库提交 |
| 是否需要 key | 否。四个数据源都免费公开，无需注册 |
| 改动站内数据 | 不会。脚本只读 `_species/*.md`，只写缓存与 CSV |

## 2. 数据源与许可

### 2.1 GBIF Backbone Taxonomy
- 接口：`GET https://api.gbif.org/v1/species/match?name=<学名>&kingdom=Animalia`
- 取用字段：`usageKey`、`scientificName`、`canonicalName`、`rank`、`status`（ACCEPTED / SYNONYM / DOUBTFUL）、`confidence`、`matchType`、`acceptedUsageKey`；异名时再查 `GET /v1/species/{acceptedUsageKey}` 取接受名。
- 链接：`https://www.gbif.org/species/<usageKey>`
- 许可：GBIF Backbone 元数据 CC BY 4.0，使用时须署名 GBIF（站点已在数据页与区块脚注署名）。
- 免费、无 key；礼貌请求（全局限速 6 req/s、8 并发、指数退避）。

### 2.2 Catalogue of Life（ChecklistBank）
- 接口：`GET https://api.checklistbank.org/dataset/3LR/match/nameusage?q=<学名>`
- 取用字段：`usage.id`、`usage.status`、`usage.label`、`usage.rank`、`usage.classification[0]`（异名时的接受名）；`type`（exact / variant / none）。
- 链接：`https://www.checklistbank.org/dataset/3LR/taxon/<id>`
- 版本：数据集别名 `3LR` 指向当前 COL 年度发布（缓存里记录实际 dataset key、DOI、日期；示例：key 316595，doi 10.48580/dgzh4）。换版时改 `_config.yml` 的 `external.col_taxon` 与脚本常量 `COL_DATASET`。
- 免费、无 key。

### 2.3 Wikidata
- 接口：`https://query.wikidata.org/sparql`，按 **P225（分类单元学名）** 精确匹配，一批 120 个学名一次查询，失败自动二分重试。
- 链接：`https://www.wikidata.org/wiki/<QID>`
- 许可：CC0 1.0。

### 2.4 Blattodea Species File（世界名录，含原 Isoptera Species File）
- 站点：`https://cockroach.speciesfile.org`（TaxonWorks / TaxonPages，MIT 开源；无稳定公开 API，见第 5 节）。
- 只用于物种页外链与人工核对工作表，不参与一致性判定。

### 2.5 判定规则（为什么有些名没有外链）
- **GBIF 外链门槛**：`matchType` 为 `EXACT`，或为 `FUZZY` 且 `confidence ≥ 95`；且返回阶元必须是 `SPECIES` / `SUBSPECIES`。属级、科级或低置信度的模糊结果一律不给链接（否则会把「属级近似」误当成本种）。
- **COL 外链**：只要 ChecklistBank 返回了 name usage 记录就给链接，并标注 accepted / synonym。
- **一致性提示**：见第 4 节的标记表。

## 3. 生成与刷新

```bash
# 只统计（不写文件）：查看还差多少条
python .github/workflows/build_authority_links.py

# 增量抓取并写入缓存 + CSV（默认只补缺）
python .github/workflows/build_authority_links.py --write

# 定时/手动刷新：重抓 30 天前的条目，最多花 10 分钟
python .github/workflows/build_authority_links.py --write --refresh --stale-days 30 --budget 600

# 全部重抓（换 COL 年度版本后建议执行）
python .github/workflows/build_authority_links.py --write --refresh-all

# 校验已提交缓存（CI 用，不联网）
python .github/workflows/build_authority_links.py --check

# 统计报告
python .github/workflows/build_authority_links.py --report
```

- 抓取 3071 个学名 × 2 个接口 ≈ 6100 次请求，约 20 分钟（8 并发、6 req/s）。中断后重跑自动续传。
- 每个条目的 `_d` 字段记录抓取日期，`--refresh --stale-days N` 只重抓过期条目。
- CI（`.github/workflows/pages.yml`）在 Jekyll 构建前执行一次有限预算的刷新（`--budget 120`），因此部署版会比仓库缓存略新；仓库缓存本身由维护者定期 `--write` 后提交。

## 4. 一致性标记（flags）

缓存里每个学名有 `flags` 数组，物种页据此显示提示；CSV 里的 `consistency` 列给出中文说明。

| flag | 含义 | 页面表现 |
|---|---|---|
| （空） | 与 GBIF、COL 的接受名一致 | ✔ 绿色「与接受名一致」 |
| `gbif_synonym` | GBIF 把本站名处理为异名 | 黄色冲突块，给出 GBIF 接受名与链接 |
| `col_synonym` | COL 把本站名处理为异名 | 同上（COL 接受名） |
| `gbif_doubtful` | GBIF 标记 DOUBTFUL | 黄色提示 |
| `gbif_fuzzy` | GBIF 仅模糊匹配（未达外链门槛） | 黄色提示 |
| `gbif_missing` / `col_missing` | 对应库未收录 | 黄色提示 |
| `gbif_rank_mismatch` / `col_rank_mismatch` | 外部库阶元与本站记录不同 | 黄色提示 |

重要说明：
- 本站采用 Engel 等（2024）体系与原始文献的处理（例如 Heterotermitidae 与部分传统 Rhinotermitidae 的归属），而 GBIF Backbone 的分类更新有滞后，因此**分类级别（科/亚科）差异不写入站内数据**，也不做自动「纠正」。
- 异名提示仅表示「外部库把该名视为异名」，不代表本站错误：本站可能有意采用该名为有效名。是否修订由人工判断，依据见各物种页的模式产地、次异名与文献。
- 提示文案中的「本站数据未改动」是硬性约定：脚本没有写 `_species/` 的代码路径。

## 5. 世界名录对照（Blattodea Species File）

BSF 已并入原 Isoptera Species File，覆盖蜚蠊与白蚁，提供命名、文献、模式标本、分布与图片。它由 TaxonPages / TaxonWorks 构建，**没有稳定公开 API**，所以采用「半自动」流程：

1. `build_bsf_links.py` 通过 BSF 页面所用的公开 TaxonWorks 接口按学名自动检索 OTU，生成 `_data/bsf_links.json`；
2. 同时导出人工核对工作表 `_tools/bsf对照/工作表.csv`（含自动匹配结果与待核对列）；
3. 人工核对后在表里把 `check_status` 改为 `已核对`，用 `--import` 合并回缓存，物种页才会显示「已人工核对」徽章；
4. 未核对的自动匹配条目显示「自动匹配」，未检索到的显示「未检索到」，匹配不确定的显示「匹配不确定，待人工核对」。

详见 `_tools/bsf对照/操作说明.md`。BSF 深链格式：`https://cockroach.speciesfile.org/otus/<OTU_ID>/overview`。

## 6. 结构化数据（JSON-LD）

物种页由 `_includes/species-jsonld.html` 输出 `@graph`：

- `Taxon`：`name`、`scientificName`（含命名人年份）、`taxonRank`、`alternateName`（中文正名）、`parentTaxon`、`sameAs`（GBIF / COL / Wikidata / BSF）、`identifier`（PropertyValue：GBIF usageKey、COL ID、Wikidata QID）、`url`、`isPartOf`（指向站点 Dataset 实体 `#dataset`）。
- `BreadcrumbList`：名录 → 科 →（亚科）→ 属 → 种/亚种，位置与页面面包屑一致。

首页（`index.md` / `en/index.md` / `es/index.md`）的 `Dataset` JSON-LD 已加固定 `@id`，三语页面与全部物种页共享同一实体 ID，形成 `Dataset ← isPartOf ← Taxon` 的实体图。JSON-LD 字段在数据缺失时自动省略（例如没有 Wikidata 条目时不输出对应 `sameAs`），不会输出空数组。

## 7. 已知限制

- 外部库更新滞后（尤其 GBIF Backbone 与 COL 对 2024 年后新组合、新亚科的收录），故「未收录」不等于名称无效。
- COL 年度发布换版后，旧 usage id 可能失效；脚本按学名重新匹配，链接会跟着更新。
- Wikidata 的 P225 只收录有独立条目的分类单元；冷门种通常没有 QID，属于正常情况。
- 仅按学名匹配，未使用模式标本、命名人消歧；同名异物（不同界）已通过 `kingdom=Animalia` 限制，但同名属/种异名关系仍可能出现，故异名提示需人工判断。
- 抓取日期与数据源版本都记录在 `_data/authority_links.json` 的 `meta` 中，物种页脚注显示抓取日期。
