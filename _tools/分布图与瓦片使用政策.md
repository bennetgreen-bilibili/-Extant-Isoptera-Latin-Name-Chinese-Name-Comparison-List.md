# 分布图与瓦片使用政策

> 本文档说明「分布图」功能的数据流水线、聚合口径、化石过滤、瓦片使用政策与复现方法。
> 相关文件全部在仓库内，脚本可 `--check` 校验，产物随仓库提交。

| 类别 | 路径 |
| --- | --- |
| 生成脚本 | `.github/workflows/build_occurrence_geojson.py` |
| 科级 GeoJSON | `assets/geo/family/<family_id>.geojson`（13 个） |
| 属级 GeoJSON | `assets/geo/genus/<genus_id>.geojson`（每个有记录的属一个） |
| 种级 GeoJSON | `assets/geo/species/<slug>.geojson`（每个有记录的种/亚种一个） |
| 汇总数据（Liquid） | `_data/occurrence_summary.json` → `site.data.occurrence_summary` |
| 页面片段 | `_includes/distribution-map.html`（`mode="family"` / `mode="genus"` / `mode="species"`） |
| 说明片段 | `_includes/distribution-notes.html`（名录页顶部的「分布图怎么读」折叠块） |
| 地图脚本 / 样式 | `assets/map.js`、`assets/map.css` |
| 本地 Leaflet | `assets/vendor/leaflet/`（leaflet.js / leaflet.css / images/ / LICENSE / README.md） |
| 页面 | `list.md` / `en/list.md` / `es/list.md`（科、属标题下方）与每个 `_species/*.md` 页面 |
| 本地缓存 | `_tmp/gbif_cache/`（`.gitignore` 已忽略，不入库） |

---

## 1. 页面布局（2026-10 改版）

分布图不再是独立页面，也不再在物种页只放链接：

- **名录页**：每个 `<h3 id="<科id>">` 科级标题下方插一张科级地图；每个 `<h5 id="<属id>">` 属级标题下方插一张属级地图。插入方式是在 `list.md` 里写一行
  `{% include distribution-map.html mode="family" id="mastotermitidae" %}`（属级同理），由 include 从 `occurrence_summary` 里取数；某个科/属没有数据时 include 输出空，不影响排版。
- **物种页**：`_layouts/species.html` 用 `{% include distribution-map.html mode="species" %}` 输出该种自己的种级地图；GBIF 中没有该种带坐标记录时显示一句说明。
- **说明区块**：名录页顶部（搜索框之后、目录之前）用 `{% include distribution-notes.html %}` 放一个折叠的「分布图怎么读」，交代方法、化石过滤、采样偏差、来源与瓦片政策。
- 地图窗口已放大：科级 520 px、属级 420 px、种级 480 px（桌面），窄屏逐级缩小到 300–400 px。

## 2. 数据流水线

1. **分类键**：从 `data/index.json` 读取 13 个科；从 `_species/*.md` 的 front matter 读取 323 个属（`genus_id` / `genus_latin`）与 3071 个种/亚种（slug、`family_id`、`genus_id`）。每个属名请求一次
   `https://api.gbif.org/v1/species/match?name=<GENUS>&rank=GENUS` 取 `usageKey`（结果缓存）。
2. **种级 GBIF 键**：直接用 `_data/authority_links.json` 里已有的 GBIF 匹配结果（由 `build_authority_links.py` 生成）：接受名取 `gbif.key`，异名取 `gbif.accepted.key`；只匹配到属/科以上阶元的种（当前 104 个）没有种级地图。这一步**不发请求**。
3. **出现记录**：按**属**请求 `occurrence/search`，固定参数
   `taxonKey=<属键>&hasCoordinate=true&hasGeospatialIssue=false&limit=300&offset=…`，按 `offset` 翻页。
   每个属都拉全该属的带坐标记录（记录耗尽即停；上限 30000 条只作为安全阈值）。
   每条记录只保留 `key / lat / lon / basisOfRecord / taxonRank / acceptedTaxonKey / speciesKey / genusKey / countryCode`，
   按属缓存到 `_tmp/gbif_cache/occ_genus_<属键>.json`（解析后的紧凑格式，不是整页原始 JSON）。
4. **归户与化石过滤**（见 §3）：把记录归到名录里的种 / 属 / 科；不属于名录的分类单元一律丢弃。
5. **1° 网格聚合**：格号 `(floor(lat), floor(lon))`，要素坐标取格心 `(floor+0.5, floor+0.5)`，保留三位小数；同格记录数记为 `n`。
6. **输出**：每个有数据的分类单元一个 `FeatureCollection`，`properties` 写 `level / records / cells / grid / taxon_scope: "checklist_extant" / generated / source` 以及该单元的名称与父级 id。
7. **汇总**：`_data/occurrence_summary.json` 结构为 `{meta, families:[], genera:[], species:{slug: …}}`，其中 `species` 是**以 slug 为键的字典**，物种页模板直接 `occ.species[slug]` 取值，避免 3000 多次循环。

## 3. 化石过滤（2026-10 修复）

旧版地图按 GBIF 科键取样，于是同一科/属里 **已灭绝的化石种**（琥珀内含物、压痕化石）的记录也画了进去，表现为欧洲、缅甸等琥珀产地的孤立点。现在有三道过滤：

1. **只认名录内的分类单元**：本名录只收现生类群，因此 GBIF 中任何不在名录里的物种（= 全部化石种 / 已灭绝种 / 未收录的现生种）的记录都不会被归户，直接丢弃。记录若只鉴定到属，则按属归户（属必须在本名录内）。
2. **按 `basisOfRecord` 剔除**：`FOSSIL_SPECIMEN` 与 `MATERIAL_CITATION` 两类记录一律 dropped，避免「化石标本被误鉴定为现生种」这类脏数据混入。
3. **页面上写明口径**：每张图与「分布图怎么读」都注明「仅名录现生类群」，GeoJSON 的 `properties.taxon_scope` 与 `source` 里也有同样说明。

> 旧版「按属汇总四个科」的做法（Hodotermopsidae / Psammotermitidae / Termitogetonidae / Heterotermitidae）已不再需要：现在所有图都从属级取样聚合而来，科级图 = 该科所有属的证据之和，因此不会再和 GBIF 宿主科重复计数。

## 4. 取数口径的理由

- **按属取全量**：保证每个属、每个种都有机会出现在地图上。早期版本按科取 900 条、后来按属取 300–3000 条，结果是大属里的稀有种一条记录都轮不到，种级地图出现大片空白；现在每个属都拉全（上限 30000 条只是防止异常数据的安全阈值），合计约 12 万条带坐标记录。
- **可复现**：GBIF 按记录键序稳定返回，同一份缓存重跑结果逐字节相同；只有 GBIF 数据本身变化时才会变。

## 5. 礼貌抓取与可恢复

- **User-Agent**：`IsopteraChecklistBot/1.0 (termite checklist distribution maps; +https://github.com/bennetgreen-bilibili/-Extant-Isoptera-Latin-Name-Chinese-Name-Comparison-List.md)`。
- **限速**：请求间隔 0.5 s，串行请求（GBIF occurrence/search 单页响应约 2 MB，且服务端本身有排队；并发不会更快）。
- **退避**：429 / 5xx / 网络错误按 2→3.6→6.5→…→30 s 指数退避，最多 7 次尝试。
- **缓存粒度**：每个属的解析后记录单独缓存；一个属抓完就落盘，中断后重跑从中断的属继续。单个属请求失败只跳过该属并继续（不会中止整次构建）。
- **时间预算**：`--budget <秒>`（默认 1200）。用尽时脚本**写出已完成的部分**（`meta.partial: true`），缓存保留，重跑继续；建议全量刷新时给 `--budget 21600`。

## 6. 地图与瓦片使用政策

### 6.1 底图选择

**首选 GBIF 公共栅格瓦片**：

```
https://tile.gbif.org/3857/omt/{z}/{x}/{y}@1x.png?style=gbif-natural-en
```

理由：

1. GBIF 在 <https://tile.gbif.org/> 明确写明这些瓦片「for use on GBIF.org **and by users of our API**」，且「Both the vector and raster tiles are available for public use」——即公开可用，无需申请密钥。
2. 数据本身来自 GBIF，底图与数据同源，署名与许可说明可以一并给出（© OpenStreetMap contributors，经 OpenMapTiles schema 生成）。
3. 相比直接打 OSM 官方瓦片，把负载放在 GBIF 自己的瓦片服务上更合适：我们的读者正是在看 GBIF 数据。

**回退**：若 GBIF 瓦片连续 3 次加载失败（服务异常、被网络阻断等），自动切换到
`https://tile.openstreetmap.org/{z}/{x}/{y}.png`，同时把署名换成 OSM 的署名，并对每个瓦片 `<img>` 设置
`referrerpolicy="no-referrer-when-downgrade"`。OSM 瓦片政策见
<https://operations.osmfoundation.org/policies/tiles/>。

署名文案：`GBIF base map | © OpenStreetMap contributors`（含指向 OSM 版权页的链接）。

### 6.2 合规清单

| 要求 | 本站在哪里做到 |
| --- | --- |
| 不把公共瓦片当「无限免费 CDN」 | 名录页每张地图、每个物种页一张地图，但**只有滚动进视口的那一张**才会创建并请求瓦片；不预取、不做服务端抓取 |
| 不预取屏幕外的瓦片 | `assets/map.js` 用 `IntersectionObserver`（`rootMargin: 0px`）**进入视口才** `L.map()`，之前容器里只有一行占位文字 |
| 不做服务端抓瓦片 / 不批量下载 | 生成脚本只调 GBIF **数据** API，从不请求瓦片；瓦片全部由读者浏览器按需获取 |
| 限制瓦片总量 | 地图 `maxZoom = 9`（数据仅 1° 精度）；单页地图虽多（名录页 13 + 323 张），但同一时刻只有读者滚到的少数几张在请求瓦片 |
| 保留署名 | `L.tileLayer` 的 `attribution`；Leaflet 的 attribution 控件常显 |
| 正确的 referrer 策略 | 回退到 OSM 时逐瓦片设置 `referrerpolicy="no-referrer-when-downgrade"` |
| 本地托管库，不依赖第三方 CDN | Leaflet 1.9.4 已 vendor 到 `assets/vendor/leaflet/`（含 LICENSE），运行时零 CDN 请求 |
| 尊重 `prefers-reduced-motion` | `assets/map.css` 关掉缩放过渡 |
| 不劫持页面滚动 | `scrollWheelZoom: false`，需要缩放时用 +/− 控件 |
| 数据再分发署名 | 名录页「分布图怎么读」给出 GBIF 引用指南 <https://www.gbif.org/citation-guidelines>、OSM 版权页与 Leaflet 许可 |

> 说明：GBIF 的引用指南针对「下载」建议用带 DOI 的 occurrence download 引用。本功能走的是 `occurrence/search` API 逐页取数（不生成 download DOI），因此按「GBIF.org + 访问日期 + API 端点」披露来源，并在 `_data/occurrence_summary.json` 的 `meta.citation` 里保留引用指南链接。若日后需要严格意义上的 DOI 引用，可改用 GBIF 的 download API 生成一次下载并引用其 DOI，届时只需替换 `source` 字段与页面文案。

### 6.3 渲染细节（`assets/map.js`）

- `.distribution-map[data-geojson]` 元素：`data-label`（无障碍标签）、`data-legend`、`data-unit`、`data-empty`、`data-loading` 均由 include 按页面语言注入。
- `L.geoJSON` + `pointToLayer` → `L.circleMarker`：半径 `2.2 + 9.8·√(n/maxN)`，填充透明度 `0.26 + 0.5·√(n/maxN)`。
- `fitBounds`（`padding: [14,14]`, `maxZoom: 8`）自动取景；无要素时在容器里显示本地化的「无数据」提示，不创建地图。
- 图例为 `L.control`（右下角），给出 1 / 中位 / 最大三档圆圈与「记录 / 网格」标题。
- 数据请求失败（404、离线）同样降级为容器内提示，不抛异常、不阻塞页面。

### 6.4 资源加载位置（谁引哪张表）

- `_layouts/default.html`（由 Lead 维护）：`page.url` 含 `/list` **或** `page.collection == 'species'` 时在 `<head>` 载入
  `assets/vendor/leaflet/leaflet.css` 与 `assets/map.css`，在页面末尾以 `defer` 载入
  `assets/vendor/leaflet/leaflet.js` 与 `assets/map.js`：

  ```liquid
  {% if page.url contains '/list' or page.collection == 'species' %}<link rel="stylesheet" href="{{ site.base_url }}/assets/vendor/leaflet/leaflet.css">
  <link rel="stylesheet" href="{{ site.base_url }}/assets/map.css?v={{ site.time | date: '%s' }}">
  {% endif %}
  ...
  {% if page.url contains '/list' or page.collection == 'species' %}<script src="{{ site.base_url }}/assets/vendor/leaflet/leaflet.js" defer></script>
  <script src="{{ site.base_url }}/assets/map.js?v={{ site.time | date: '%s' }}" defer></script>
  {% endif %}
  ```

- 兜底：`assets/map.js` 若发现页面缺少 leaflet 样式表，会按 `<script>` 里 `leaflet.js` 的 `src` 推导出同目录的
  `leaflet.css` 并补一张，避免布局漏引时地图塌陷。

## 7. 复现与刷新

```bash
# 校验已提交的产物是否与脚本一致（不写文件，CI 友好；默认模式）
python .github/workflows/build_occurrence_geojson.py --check

# 生成 / 更新（复用缓存，绝不重复请求 GBIF）
python .github/workflows/build_occurrence_geojson.py --write

# 数据过期时强制重新抓取（会清空 _tmp/gbif_cache/ 并刷新访问日期）
python .github/workflows/build_occurrence_geojson.py --write --refresh --budget 21600

# 只重建某几个属（调试用；不会删除其它产物）
python .github/workflows/build_occurrence_geojson.py --write --only mastotermes,zootermopsis

# 重新 vendor Leaflet（升级版本时改脚本里的 LEAFLET_VERSION）
python .github/workflows/build_occurrence_geojson.py --vendor-leaflet
```

- `--check` 退出码：0 = 一致，1 = 有差异/缺文件，2 = 网络问题。
- **不要把它接进 CI 的每次构建**：从零抓取要数小时（GBIF 单页响应约 2 MB，本站线路 20–90 s/页），而产物已经提交在仓库里、且是确定性的。需要守卫时在本机 `--write` 之后跑 `--check`（有 `_tmp/gbif_cache/` 时零网络请求）。若确实要在 CI 里跑，应先缓存 `_tmp/gbif_cache/`（actions/cache），并只在 `--refresh` 的手动触发下执行 `--write`。
- 脚本打印每个属的 `cap / got / total` 与请求统计，便于核对进度。
- 产物格式（便于 code review）：第一行 `type`，第二行 `properties`，之后**一行一个要素**，因此 diff 只出现在变化的格子上。
- 脚本自带 JSON 自检（写入前 `json.loads`）；`--write` 会删除 `assets/geo/` 下本次未生成的旧文件（`--only` 模式除外）。

## 8. 已知局限

1. **采样偏差**：北美与欧洲过密，热带稀疏；空白多为「未采样」。
2. **覆盖偏差**：只取带坐标的记录；约三分之二的种在 GBIF 中没有任何带坐标记录，种页会显示「暂未找到」，这不代表该种不存在。
3. **种级覆盖**：104 个种在 GBIF 分类骨架里只匹配到属级（`gbif_higherrank`），没有种级地图，页面显示「暂未找到」。
4. **网格精度**：1° 聚合无法表达狭域分布（如单岛特有种）。
5. **非分布区**：没有做分布区推演，也没有剔除室内 / 逸散记录。
6. **会随时间变化**：GBIF 每日更新，重跑会改变数字与访问日期。
