# 分布图与瓦片使用政策

> 本文档说明「分布图」功能（feature 4）的数据流水线、聚合口径、瓦片使用政策与复现方法。
> 相关文件全部在仓库内，脚本可 `--check` 校验，产物随仓库提交。

| 类别 | 路径 |
| --- | --- |
| 生成脚本 | `.github/workflows/build_occurrence_geojson.py` |
| 科级 GeoJSON | `assets/geo/family/<family_id>.geojson`（13 个） |
| 属级 GeoJSON | `assets/geo/genus/<genus_id>.geojson`（可选，见 §5） |
| 汇总数据（Liquid） | `_data/occurrence_summary.json` → `site.data.occurrence_summary` |
| 页面片段 | `_includes/distribution-map.html`（`mode="page"` / `mode="link"`） |
| 地图脚本 / 样式 | `assets/map.js`、`assets/map.css` |
| 本地 Leaflet | `assets/vendor/leaflet/`（leaflet.js / leaflet.css / images/ / LICENSE / README.md） |
| 页面 | `distribution.md`、`en/distribution.md`、`es/distribution.md` |
| 本地缓存 | `_tmp/gbif_cache/`（`.gitignore` 已忽略，不入库） |

---

## 1. 为什么是「科 / 属」而不是「种」

种级分布图意味着 3071 个物种页各自加载一组瓦片与一份数据。以本站的访问量级与公共瓦片服务的免费额度，这是不合适的；而且 1° 网格的聚合结果本身就被采样强度主导，种级精度带来的信息增量极小。

因此采用用户已确认的折中：**科级必须、属级可选、种级不做**。物种页只放一个指向科级地图的链接（`mode="link"`），不加载 Leaflet、不请求任何瓦片（只额外引用一张 5 KB 的 `assets/map.css` 给这个区块上样式）。

## 2. 数据流水线

1. **分类键**：从 `data/index.json` 的分类树读取 13 个科（id / 拉丁名 / 中文名），逐个请求
   `https://api.gbif.org/v1/species/match?name=<FAMILY>&rank=FAMILY`，取 `usageKey`（canonical）。
2. **出现记录**：`https://api.gbif.org/v1/occurrence/search`，固定参数
   `taxonKey=<key>&hasCoordinate=true&hasGeospatialIssue=false&limit=300&offset=…`，
   按 `offset` 翻页，直到记录耗尽或达到 **每科 900 条** 上限；只保留 `decimalLatitude` / `decimalLongitude`（以及统计用的 `countryCode`）。
3. **1° 网格聚合**：格号 `(floor(lat), floor(lon))`，要素坐标取格心 `(floor+0.5, floor+0.5)`，保留三位小数；同格记录数记为 `n`。
4. **输出**：每科一个 `FeatureCollection`，`properties` 里写 `family / family_zh / gbif_key / resolution / records / cells / grid / generated / source`（按属汇总的科另加 `gbif_keys` 与 `note`）。
5. **汇总**：`_data/occurrence_summary.json` 汇总 `meta`（访问日期、上限、网格、许可、方法说明）、`families`（含各国记录数 top 8）与 `genera`。

### 2.1 分类骨架差异（重要）

GBIF Backbone 与本站采用的分类（Engel 2021 及后续）并不一致，以下 4 个科在 GBIF 中没有同名科：

| 本站科 | 在 GBIF 中被并入 |
| --- | --- |
| 原白蚁科 Hodotermopsidae | 古白蚁科 Archotermopsidae |
| 沙白蚁科 Psammotermitidae | 鼻白蚁科 Rhinotermitidae |
| 寡脉白蚁科 Termitogetonidae | 鼻白蚁科 Rhinotermitidae |
| 异白蚁科 Heterotermitidae | 鼻白蚁科 Rhinotermitidae |

脚本对这 4 科改用 **按属汇总**（`resolution: "genus_aggregate"`）：逐个匹配属名取 `taxonKey`，合并各属记录后仍以 900 条为限，`gbif_key` 记为 `null`、`gbif_keys` 记各属键。这样地图与本名录的分类一致，代价是这 4 科的记录同时计入 GBIF 的宿主科——即它们与鼻白蚁科、古白蚁科的地图**有重叠**。这是被如实记录、并在页面上明确说明的已知偏差，不是 bug。

其他科（含杆白蚁科 Stylotermitidae）在 GBIF 中有独立的科级键，直接使用（`resolution: "family_key"`）。

## 3. 记录上限与聚合口径的理由

- **每科 900 条**：`occurrence/search` 每页最多 300 条，900 = 3 页。这个量级足以呈现采样格局（记录数以千计的科也只取前 900 条），同时把一次全量生成的请求数控制在 200 次以内。
- **可复现但非随机**：GBIF 按记录键序稳定返回，因此「前 900 条」是确定性样本，不同机器、不同日期跑出同样的集合（除非 GBIF 数据本身变化）。它**不是**随机抽样，会偏向键值小的数据集；这一点已写进页面的「局限」区块，不做掩饰。
- **1° 网格**：约 111 km，与「科级分布格局」的分辨率匹配；更细的网格会让文件变大而信息量不增。
- **格心坐标**：让每个点代表格子而不是某个具体采集点，避免读者把聚合点误读为精确产地。
- **确定性**：`generated` 取缓存首次抓取的日期（`_tmp/gbif_cache/_meta.json`），因此**同一份缓存重跑，产物逐字节相同**；只有 `--refresh` 会更新访问日期。这让 `--check` 可以进 CI 做产物守卫。

## 4. 礼貌抓取与可恢复

- **User-Agent**：`IsopteraChecklistBot/1.0 (termite checklist distribution maps; +https://github.com/bennetgreen-bilibili/-Extant-Isoptera-Latin-Name-Chinese-Name-Comparison-List.md)`。
- **限速**：请求间隔 0.4 s（约 2.5 req/s）。
- **退避**：429 / 5xx / 网络错误按 1→2→4→8→16 s 指数退避，最多 6 次尝试。
- **缓存**：每个请求的响应落在 `_tmp/gbif_cache/<name>.json`，**重跑永不重复请求**；中断后用同样的命令再跑即可从中断处继续。
- **时间预算**：`--budget <秒>`（默认 1200）。用尽时脚本以退出码 2 结束且**不写任何文件**，避免产出半成品；缓存保留，重跑继续。

## 5. 属级图层（可选）

- 只取 `_data/species_by_genus.json` 中 **物种数 ≥ 12** 的属（当前 54 个满足）。
- 再限制为**最大的 12 个属**（`--max-genera`，按物种数降序、同数按 id 排序，结果确定）。取 12 而不是 54，是因为属级每页仍要请求 300 条记录、单页响应约 2.4 MB：54 个属会让一次全量生成的流量翻两番，而 12 个属（约 1400 种，含 Nasutitermes / Odontotermes / Microcerotermes / Reticulitermes 等最常被记录的大属）已足够展示属级图层。想扩大：`--max-genera 54`。
- 每个文件必须 **< 60 KB**，超出则跳过（当前不会触发）。
- 属级文件总量 **< 3 MB**，超出时按物种数从小到大依次丢弃，并打印被丢弃的属。
- 关掉属级：`--no-genera`；调整数量：`--max-genera N`。

页面会自动跟随数据：`occ.genera` 为空时，`/distribution/` 不渲染属级区块；物种页的 `mode="link"` 也只在 `site.data.occurrence_summary.genera` 里能找到该属时才输出属级深链接，否则安静回退到科级链接。

## 6. 地图与瓦片使用政策

### 6.1 底图选择

**首选 GBIF 公共栅格瓦片**：

```
https://tile.gbif.org/3857/omt/{z}/{x}/{y}@1x.png?style=gbif-natural-en
```

理由：

1. GBIF 在 <https://tile.gbif.org/> 明确写明这些瓦片「for use on GBIF.org **and by users of our API**」，且「Both the vector and raster tiles are available for public use」——即公开可用，无需申请密钥。
2. 数据本身来自 GBIF，底图与数据同源，署名与许可说明可以一并给出（© OpenStreetMap contributors，经 OpenMapTiles schema 生成）。
3. 相比直接打 OSM 官方瓦片，把负载放在 GBIF 自己的瓦片服务上更合适：我们的读者正是在看 GBIF 数据。

**回退**：若 GBIF 瓦片连续 3 次加载失败（服务异常、被网络阻断等），自动切换到
`https://tile.openstreetmap.org/{z}/{x}/{y}.png`，同时把署名换成 OSM 的署名，并对每个瓦片 `<img>` 设置
`referrerpolicy="no-referrer-when-downgrade"`。OSM 瓦片政策见
<https://operations.osmfoundation.org/policies/tiles/>。

署名文案：`GBIF base map | © OpenStreetMap contributors`（含指向 OSM 版权页的链接）。

### 6.2 合规清单

| 要求 | 本站在哪里做到 |
| --- | --- |
| 不把公共瓦片当「无限免费 CDN」 | 只在 `/distribution/` 一页用图；种级页面不加载地图 |
| 不预取屏幕外的瓦片 | `assets/map.js` 用 `IntersectionObserver`（`rootMargin: 0px`）**进入视口才** `L.map()`，之前容器里只有一行占位文字 |
| 不做服务端抓瓦片 / 不批量下载 | 生成脚本只调 GBIF **数据** API，从不请求瓦片；瓦片全部由读者浏览器按需获取 |
| 限制瓦片总量 | 地图 `maxZoom = 9`（数据仅 1° 精度）；单页最多 13 + 12 张地图，且只有滚动到的才会初始化 |
| 保留署名 | `L.tileLayer` 的 `attribution`；Leaflet 的 attribution 控件常显 |
| 正确的 referrer 策略 | 回退到 OSM 时逐瓦片设置 `referrerpolicy="no-referrer-when-downgrade"` |
| 本地托管库，不依赖第三方 CDN | Leaflet 1.9.4 已 vendor 到 `assets/vendor/leaflet/`（含 LICENSE），运行时零 CDN 请求 |
| 尊重 `prefers-reduced-motion` | `assets/map.css` 关掉缩放过渡 |
| 不劫持页面滚动 | `scrollWheelZoom: false`，需要缩放时用 +/− 控件 |
| 数据再分发署名 | 页面「来源与许可」区块给出 GBIF 引用指南 <https://www.gbif.org/citation-guidelines>、OSM 版权页与 Leaflet 许可 |

> 说明：GBIF 的引用指南针对「下载」建议用带 DOI 的 occurrence download 引用。本功能走的是 `occurrence/search` API 逐页取数（不生成 download DOI），因此页面按「GBIF.org + 访问日期 + API 端点」披露来源，并在 `_data/occurrence_summary.json` 的 `meta.citation` 里保留引用指南链接。若日后需要严格意义上的 DOI 引用，可改用 GBIF 的 download API 生成一次下载并引用其 DOI，届时只需替换 `source` 字段与页面文案。

### 6.3 渲染细节（`assets/map.js`）

- `.distribution-map[data-geojson]` 元素：`data-label`（无障碍标签）、`data-legend`、`data-unit`、`data-empty`、`data-loading` 均由 include 按页面语言注入。
- `L.geoJSON` + `pointToLayer` → `L.circleMarker`：半径 `2.2 + 9.8·√(n/maxN)`，填充透明度 `0.26 + 0.5·√(n/maxN)`。
- `fitBounds`（`padding: [14,14]`, `maxZoom: 8`）自动取景；无要素时在容器里显示本地化的「无数据」提示，不创建地图。
- 图例为 `L.control`（右下角），给出 1 / 中位 / 最大三档圆圈与「记录 / 网格」标题。
- 数据请求失败（404、离线）同样降级为容器内提示，不抛异常、不阻塞页面。

### 6.4 资源加载位置（谁引哪张表）

- `_layouts/default.html`（由 Lead 维护）：`page.url` 含 `/distribution` 时在 `<head>` 载入
  `assets/vendor/leaflet/leaflet.css` 与 `assets/map.css`，在页面末尾以 `defer` 载入
  `assets/vendor/leaflet/leaflet.js` 与 `assets/map.js`。所需片段：

  ```liquid
  {% if page.url contains '/distribution' %}<link rel="stylesheet" href="{{ site.base_url }}/assets/vendor/leaflet/leaflet.css">
  <link rel="stylesheet" href="{{ site.base_url }}/assets/map.css?v={{ site.time | date: '%s' }}">
  {% endif %}
  ...
  {% if page.url contains '/distribution' %}<script src="{{ site.base_url }}/assets/vendor/leaflet/leaflet.js" defer></script>
  <script src="{{ site.base_url }}/assets/map.js?v={{ site.time | date: '%s' }}" defer></script>
  {% endif %}
  ```

- 物种页的 link 模式：include 只追加 `assets/map.css`（5 KB，无瓦片、无 Leaflet）。
- 兜底：`assets/map.js` 若发现页面缺少 leaflet 样式表，会按 `<script>` 里 `leaflet.js` 的 `src` 推导出同目录的
  `leaflet.css` 并补一张，避免布局漏引时地图塌陷。

## 7. 复现与刷新

```bash
# 校验已提交的产物是否与脚本一致（不写文件，CI 友好；默认模式）
python .github/workflows/build_occurrence_geojson.py --check

# 生成 / 更新（复用缓存，绝不重复请求 GBIF）
python .github/workflows/build_occurrence_geojson.py --write

# 数据过期时强制重新抓取（会清空 _tmp/gbif_cache/ 并刷新访问日期）
python .github/workflows/build_occurrence_geojson.py --write --refresh

# 小样本试跑 / 省时间
python .github/workflows/build_occurrence_geojson.py --write --limit 300 --no-genera

# 限定网络时间预算（秒）
python .github/workflows/build_occurrence_geojson.py --write --budget 240

# 重新 vendor Leaflet（升级版本时改脚本里的 LEAFLET_VERSION）
python .github/workflows/build_occurrence_geojson.py --vendor-leaflet
```

- `--check` 退出码：0 = 一致，1 = 有差异/缺文件/多余文件，2 = 网络或预算问题。
- **不要把它接进 CI 的每次构建**：一次从零抓取要 40 分钟以上（GBIF 单页响应约 2.4 MB，本站线路 20–90 s/页），而产物已经提交在仓库里、且是确定性的。需要守卫时在本机 `--write` 之后跑 `--check`（有 `_tmp/gbif_cache/` 时零网络请求）。若确实要在 CI 里跑，应先缓存 `_tmp/gbif_cache/`（actions/cache），并只在 `--refresh` 的手动触发下执行 `--write`。
- 脚本打印每科/每属的 `records / cells / KB` 与请求统计，便于核对。
- 产物格式（便于 code review）：第一行 `type`，第二行 `properties`，之后**一行一个要素**，因此 diff 只出现在变化的格子上。
- 脚本自带 JSON 自检（写入前 `json.loads`）。

## 8. 已知局限

1. **采样偏差**：北美与欧洲过密，热带稀疏；空白多为「未采样」。
2. **上限偏差**：每科前 900 条按 GBIF 键序截断，偏向早期数据集。
3. **分类重叠**：见 §2.1，4 个科与宿主科地图重叠。
4. **网格精度**：1° 聚合无法表达狭域分布（如单岛特有种），科级地图只为呈现格局。
5. **非分布区**：没有做分布区推演，也没有剔除室内 / 逸散记录。
6. **会随时间变化**：GBIF 每日更新，重跑会改变数字与访问日期。
