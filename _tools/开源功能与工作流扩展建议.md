1. **搜索能力没榨干**：Pagefind 只做了"输入框 + 结果"，没有分面、没有元数据、没有站内全局入口、没有搜索词回流；

2. **数据质量有测量、没有闸门**：所有 `--check` 都在部署 job 里 `continue-on-error: true`，坏了只标黄不拦；
   没有 PR 校验、没有外链巡检、没有缓存过期提醒、没有部署后健康检查。
3. **名录只能"看"，没有让机器 / 同行"用"的接口**：缺 DwC-A、缺 GBIF download DOI 引用、缺 JSON Schema；
   GitHub Pages 不发 CORS 头，第三方网页 fetch 不到 `search-index.json`。

## 1. P0：建议先做（每项 0.5–2 天）

### 1.1 Pagefind 升级：分面 + 元数据 + 全局快捷键 + 搜索词回流
- **开源组件**：[Pagefind](https://pagefind.app/)（已用，MIT）
- **为什么**：3068 个物种页 + 三语页面，读者第一动作是搜；现在只能先进 `/search/`，结果里看不到拉丁名 / 科 / 阶元，也不能按科筛。
- **做法**（全部复用现有索引，不新增依赖）：
  1. `_layouts/default.html` 的 `<main data-pagefind-body>` 按页面类型补属性：物种页加
     `data-pagefind-filter="family:{{ page.family_latin }}"`、`data-pagefind-filter="rank:{{ page.rank }}"`，
     以及 `data-pagefind-meta="latin:{{ page.latin }}"`、`data-pagefind-meta="zh:{{ page.zh }}"`。
  2. `assets/search-page.js` 的 `PagefindUI` 选项加 `filters`，并让 `?q=&family=` 进 URL（可分享的检索链接）。
  3. 导航栏加全局搜索：Ctrl / ⌘ + K 打开轻量浮层，直接用现有 `/pagefind/` 索引；Esc 关闭，键盘上下选择。
  4. 搜索词回流：提交时 `window.goatcounter.count({ path: "/search?q=" + q, event: true })`（GoatCounter 开源、无 Cookie），
     零后端拿到"读者在找什么"，反过来指导补中文名 / 异名。
- **涉及文件**：`_layouts/default.html`、`assets/search-page.js`、`assets/custom.css`
- **验收**：`/search/?q=白蚁&family=TERMITIDAE` 能筛出结果；任意页 Ctrl+K 可搜索；GoatCounter 面板出现 `/search?q=` 事件。
- **注意**：过滤器需要重新生成 Pagefind 索引（CI 本来每次都生成，无需改动）。

### 1.2 名录检索索引补"科 / 支系 / 阶元"字段
- **为什么**：索引缺 family / clade / genus，所以名录页搜索既不能按科筛，也不能在结果里显示"哪个科"。
- **做法**：`build_search_index.py` 从 `list.md` 标题层级补 `f`（科）、`c`（支系）、`g`（属）三个字段；
  `assets/search.js` 结果行显示"科 · 阶元"角标，并支持点角标过滤。
- **工作量**：0.5 天；`--check` 仍保证确定性输出。
- **验收**：搜 `baiyi`、`kalotermitidae` 时结果带科名；按科过滤后条数正确。

### 1.3 分发渠道补齐：Atom/RSS + JSON Feed + OpenSearch + WebSite/SearchAction
- **开源组件**：[jekyll-feed](https://github.com/jekyll/jekyll-feed)（GitHub Pages 白名单内）、
  [JSON Feed](https://www.jsonfeed.org/)、[OpenSearch 描述文档](https://github.com/dewitt/opensearch)、
  [schema.org/SearchAction](https://schema.org/SearchAction)
- **为什么**：博客只有 1 篇，但"名录变更 / 新增"才值得订阅；首页 JSON-LD 只有 Dataset，没有 `WebSite + SearchAction`，
  拿不到 Google 的站内搜索框（sitelinks searchbox）。
- **做法**：
  1. `_config.yml` 加 `plugins: jekyll-feed`，博客自动出 `/feed.xml`；head 加 `<link rel="alternate" type="application/atom+xml" href=".../feed.xml">`。
  2. 从 `dataset/CHANGELOG.md` 生成 `/changelog/` 页 + `/changelog.atom`（Liquid 手写，无需插件）：
     "2026.10.17 版：新增 X 种、改名 Y 条"——这是同行真正会订阅的内容。
  3. 根目录 `feed.json`（JSON Feed，约 30 行 Liquid）。
  4. 根目录 `opensearch.xml` + head 的 `<link rel="search" ...>`，浏览器可"添加本站为搜索引擎"。
  5. `index.md` 的 JSON-LD 增加 `WebSite` 实体与 `potentialAction`（`target` 指向 `/search/?q={search_term_string}`）。
- **工作量**：0.5–1 天。验收：`/feed.xml` 能进 Feedly；Rich Results 测试通过；`opensearch.xml` 能加进 Firefox。

### 1.4 数据校验闸门（最重要的一个工作流）
- **开源组件**：GitHub Actions（自带）+ 现有 `--check` 脚本
- **为什么**：`pages.yml` 里所有校验都 `continue-on-error: true`，**数据漂移会静默进生产**；
  也没有 `pull_request` 触发的 CI，改了 `list.md` 只能等部署后肉眼发现。
- **新建** `.github/workflows/validate.yml`（`on: pull_request` + `push`），调用新写的 `_tools/check_site.py`（纯标准库）：

| 检查 | 说明 |
|---|---|
| 三语同构 | 中 / 英 / 西 `list.md` 的物种链接 URL 集合、锚点集合完全一致（现在靠 README 口头约定） |
| 锚点完整性 | 三份 `list.md` 内所有 `#id`、物种页面包屑与同属链接目标都存在 |
| 批次一致性 | `_species/` 数量 = `search-index.json` 条数 = `sitemap.txt` 物种 URL 数 = `isoptera-data.json` 计数 |
| 幂等 | `build_species_body.py --check-idempotent`、`build_dataset.py --check`、`build_search_index.py --check`、`build_sitemap_txt.py --check` |
| 缓存合法 | 五个 `_data/*.json` 可解析；GeoJSON 与 `occurrence_summary.json` 无孤儿 / 缺失（把 `pages.yml` 那段内联 Python 挪进来复用） |
| i18n 键齐 | `_data/i18n.yml` 三语 key 集合一致 |
| 标题层级 | `list.md` 的 h3 → h5 跳级报警（顺手修成 h4，见 1.7） |
| 重名 / 空字段 | 中文正名重复（目前 2 条，需人工判断）、缺 author_year / type_locality（28 条）/ distribution（63 条） |

- **同时收紧** `pages.yml` 的 `continue-on-error`：校验类去掉，网络 / 外部 API 类保留。
- **工作量**：1.5 天（脚本 + 接线）；验收：故意删 `list.md` 一个锚点开 PR，CI 应红；恢复后绿。

### 1.5 部署后健康检查 + 外链巡检
- **开源组件**：[lychee](https://lychee.cli.rs/) / [lychee-action](https://github.com/lycheeverse/lychee-action)（Apache-2.0）
- **为什么**：站点靠外链（GBIF / COL / BSF / iNat / Commons / DOI）撑起信任，外链腐烂是必然的；
  3068 物种页 × 4–6 条外链 ≈ 1.2 万个 URL，没有巡检就等于没有维护。
- **做法**：
  1. `pages.yml` 的 `deploy` 之后加 `verify` job：curl 抽查首页、`/list/`、1 个物种页、`/sitemap.xml`、
     `/pagefind/pagefind.js`、`/search-index.json`、`/data/index.json`，断言 200 且含关键内容。
  2. 新建 `.github/workflows/linkcheck.yml`（每周 cron）：构建后跑 `lychee --offline --include-fragments _site`
     查站内链接与锚点；外链用普通 `lychee _site`（排除图床、`--max-retries 2`），失败自动开 issue。
  3. 白名单放 `lychee.toml`，长期 404 的域名加 `exclude` 并记录原因。
- **工作量**：0.5–1 天。验收：手动把一条外链改成不存在的 ID，巡检 issue 能看到。

### 1.6 物种页"引用导出" + 名录 / 物种页打印样式
- **为什么**：名录的核心用途是被引用。现在 `_includes/citation.html` 只服务数据集整体；
  单物种的 GB/T 7714、BibTeX、RIS 还得读者手抄。名录页也没有 `@media print`，打印出来是带地图和按钮的网页。
- **做法**：
  1. `assets/site.js` 加 `setupSpeciesCitation()`：从 front matter（latin / zh / author_year / family_zh）拼三种引用，
     复用现有"复制"按钮与 `document.execCommand` 回退；引用带 `/species/<slug>/` URL 与数据集 DOI。
  2. `_layouts/species.html` 加一个 `<details>`"引用本种"区块（纯前端拼，不用改 3068 页）。
  3. `assets/custom.css` 加 `@media print`：隐藏导航 / 地图 / 灯箱，表格字号与分页；
     链接后追加 URL（参考 `references.css` 里已有写法）。
- **工作量**：1 天。验收：物种页复制 BibTeX 粘进 Zotero 能识别。

### 1.7 可访性与小修（顺手一起做）
- **开源组件**：[axe-core](https://github.com/dequelabs/axe-core) / [Lighthouse CI](https://github.com/GoogleChrome/lighthouse-ci)（Apache-2.0）
- **已知问题**：`list.md` 里 h2 支系 → h3 科 → h5 属 **跳级**（323 处 h5），axe 必报 heading-order；缺 skip-link；地图容器无 `aria-label`。
- **做法**：h5 → h4（只改标签，锚点 id 不动；同步改 `assets/custom.css` 选择器与三份 `list.md`）；`<body>` 后加 skip-link；
  `_includes/distribution-map.html` 容器补 `role="img"` 与 `aria-label`。
- **CI**：`.github/workflows/a11y.yml`：本地起 http 服务后对 4 个代表页跑 axe（`npx @axe-core/cli` 或 Playwright + axe），
  只对"新出现"的违规失败（先存基线 JSON）。
- **工作量**：0.5 天（修改）+ 0.5 天（CI）。

### 1.8 纠错入口：Issue Forms + 物种页"报告错误"
- **开源组件**：GitHub Issue Forms（自带）
- **为什么**：名录靠人工维护，读者发现中文名 / 分布 / 异名错误时没有三步以内的入口，而物种页 front matter 正好能预填表单。
- **做法**：
  1. `.github/ISSUE_TEMPLATE/name-correction.yml`：学名、中文名、问题类型（命名 / 分布 / 异名 / 拼写 / 其他）、证据链接、期待值；
     `.github/ISSUE_TEMPLATE/data-question.yml` 类似。
  2. `.github/PULL_REQUEST_TEMPLATE.md`：勾选"跑过 `build_species_body.py --check-idempotent`"等。
  3. `CONTRIBUTING.md` + `_tools/纠错与贡献流程.md`：数据唯一来源、改 `list.md` 后要同步三语 + 重跑哪些脚本。
  4. `_layouts/species.html` 底部加"报告 / 建议修改"链接，用 `issues/new?template=...&title=...&body=...` 预填拉丁名、中文名、页面 URL（Liquid `uri_escape`）。
- **工作量**：0.5 天。

## 2. P1：值得排期（每项 1–3 天）

### 2.1 `/discrepancies/` 命名差异与待核对看板（推荐度最高）
- **数据已在仓库里**：`_data/authority_links.json` 的 flags（gbif_synonym 10、col_synonym 6、gbif_higherrank 104、
  col_missing 16、gbif_doubtful 21、gbif_fuzzy 4）+ `_data/bsf_links.json` 的 status（ambiguous 62、missing 43、synonym 3、已人工核对 0）。
- **为什么**：这些数字现在散在 README 里，读者看不到；而"本站名 vs 世界名录"的差异**正是这个项目的学术价值**。
  做成可筛选、可下载的表，等于把隐藏的 QA 数据变成卖点，同时给复核工作一个待办列表。
- **做法**：新脚本 `build_name_issues.py` 汇总成 `_data/name_issues.json`（拉丁名、中文名、来源、本站名、对方名、状态、链接、人工备注），
  页面 `/discrepancies/` 三语各一份 + 导出 `downloads/isoptera-name-issues.csv`；物种页黄色提示加"加入核对清单"锚点。
  过滤 / 排序用约 30 行原生 JS，不引库。
- **验收**：62 条 BSF ambiguous + 43 missing + 16 COL missing 都能筛出来并链回物种页。

### 2.2 异名落地页（699 条次异名）
- **开源组件**：[jekyll-redirect-from](https://github.com/jekyll/jekyll-redirect-from)（GitHub Pages 白名单内）或自生成 stub
- **为什么**：699 条次异名现在只是物种页里的一行字；老文献、旧数据库、搜索引擎用的多为旧名。
  给每个异名一个"接受名指向页"能接住长尾搜索，也让外部工具能解析旧名。
- **做法**：新集合 `_synonyms/`（`_config.yml` 注册，permalink `/synonym/:name/`），由 `build_synonym_pages.py`
  从 `dataset/data/isoptera-synonyms.csv` + `_species/` 生成；页面 `<link rel="canonical">` 指向接受名物种页，
  显示"异名 junior synonym"角标；slug 冲突加后缀；`build_sitemap_txt.py` 纳入新集合。
- **注意**：`jekyll-redirect-from` 在静态站点只能输出 meta refresh（不是 301）；要"可索引的旧名页"就用 stub 页 + canonical，先定目标。

### 2.3 `/qa/` 数据质量报告（自动生成，可长期盯）
- **为什么**：数据型网站的体检单；现在只能靠零散 `--check` 输出判断。
- **指标**：逐科覆盖（GBIF / COL / Wikidata / BSF / 照片 / 分布图）、缺字段（type_locality 28、distribution 63）、
  中文重名 2、异名总数 696、BSF 待复核 105（62 + 43）、外链覆盖率、缓存生成日期（2026-10-28）。
- **做法**：`build_qa_report.py` → `_data/qa.json` + `/qa/` 页面（表格 + CSS 条形图）；从 `/data/` 链入；CI 里也打印 JSON。
- **验收**：页面数字与 `--check` 输出一致；重跑 `--write` 时 diff 只出现在真变了的地方。

### 2.4 外部权威库扩容（按对本项目的价值排序）

| 来源 | 开放情况 | 价值 | 注意 |
|---|---|---|---|
| TaiCOL 臺灣物種名錄（[taicol.tw](https://taicol.tw)） | 开放数据 / 查询接口 | 台湾中文名可对照，繁体名权威来源之一 | 以站点授权与 API 说明为准；只对照不覆盖 |
| NCBI Taxonomy（[E-utilities](https://www.ncbi.nlm.nih.gov/books/NBK25501/)） | 公共 API，无 Key | 分子 / 公共健康相关引用常用 taxid | 限速约 3 req/s；只存 taxid |
| BOLD Systems（[BOLD](https://boldsystems.org/)） | 开放 API，有使用政策 | DNA 条形码簇，对"能否鉴定到种"有参考 | 条款 / 限速较严，需缓存 |
| Wikispecies（[species.wikimedia.org](https://species.wikimedia.org/)） | MediaWiki API | 近缘类群与文献入口 | 无稳定 ID，只做外链 |
| iNaturalist 分类页 | 已抓照片，可顺带存 taxon id | 观察记录数（有多少人见过） | 频率限制 60/min；可扩展现有缓存 |

- **做法**：沿用 `build_authority_links.py` 的"匹配 + 状态 + 置信度 + 只提示不改数据"模式，新增字段进 `_data/authority_links.json` 的 `taxa[name]`，
  模板 `species-authority.html` 加块；`--check` / `--refresh` / `--budget` 语义保持一致，一次只加一个来源。
- **工作量**：每个来源 1–1.5 天（含匹配规则与抽查 20 条）。

### 2.5 派生统计与图表（`/stats/` 升级）
- **开源组件**：[Chart.js](https://www.chartjs.org/)（MIT，本地托管）或 [D3](https://d3js.org/)（ISC）
- **可派生且不需要新数据**：按十年新增物种数（解析 author_year）、命名人 Top N、模式产地国家 / 大洲（从 type_locality 粗解析，需抽查）、
  每科物种数 / 属数、亚种占比。
- **做法**：`build_stats_extra.py` → `_data/stats_extra.json`（确定性输出 + `--check`），页面用 Chart.js，
  `<noscript>` 里给表格（对 AI 抓取也友好）。
- **注意**：作者年份有多作者、括号年、近似年，解析规则写进 `_tools/` 说明，解析不了的计"未识别"而不是猜。

### 2.6 Darwin Core Archive + EML（补齐 FAIR 最后一环）
- **规范**：[Darwin Core](https://dwc.tdwg.org/)、[EML](https://eml.ecoinformatics.org/)、GBIF checklist 发布流程
- **为什么**：现有 CSV / JSON / DataCite XML，**唯独缺 GBIF IPT / 注册表能直接吃的 DwC-A 包**（README 的"GBIF checklist 二次发布"就卡在这）；
  而 CSV 列名已是 Darwin Core 风格，映射成本很低。
- **做法**：`build_dataset.py` 增补 `dataset/data/dwc/{meta.xml, eml.xml, taxon.txt}` + `downloads/isoptera-dwc-a-v<ver>.zip`；
  `CHECKSUMS.sha256` 与 CHANGELOG 自动带上；`/data/` 页加下载项与字段说明。
- **验收**：用 GBIF IPT 的 checklist 校验或 `dwc` 校验脚本验证 meta.xml 引用的文件 / 字段齐全。

### 2.7 GBIF 下载 DOI（让分布图可被引用）
- **为什么**：`occurrence_summary.json.meta` 只有 `citation` 指向 GBIF 通用说明，没有 downloadKey；
  87,076 条记录没有可复现的下载凭证，审稿人会问"你引用的 GBIF 下载 DOI 是什么"。
- **做法**：用 GBIF 账号申请一次 occurrence download（`POST /occurrence/download/request`，predicate 与现有脚本一致），
  把返回的 key 与 DOI / 推荐引用写进 `occurrence_summary.json.meta`，并显示在 `/list/` 的"分布图怎么读"与 `/data/`；
  `--check` 校验字段存在；把 predicate 记进 `_tools/分布图与瓦片使用政策.md` 以便重建。
- **工作量**：0.5 天 + 等 API。收益：地图从"展示"变成"可引用数据"。

### 2.8 公开 JSON API（绕开 CORS）+ JSON Schema
- **为什么**：GitHub Pages 不发 CORS 头，第三方网页 fetch 不到 `search-index.json` / `data/*.json`；
  而仓库在 GitHub 上，用 [jsDelivr](https://www.jsdelivr.com/) 即可获得带 CORS 的 CDN 直链（`https://cdn.jsdelivr.net/gh/<user>/<repo>@main/data/index.json`），零成本。
- **做法**：① `/data/` 页加"程序化访问"区块（jsDelivr 与 raw 直链、字段说明、fetch 示例）；
  ② `dataset/schema/*.schema.json` + CI 用 `jsonschema` 校验 22 个 `data/*.json`；③ 可选：`/.well-known/dcat.jsonld` 让数据门户抓。
- **注意**：jsDelivr 有 50 MB 文件上限与 @main 缓存延迟（约 12 小时），页面注明以仓库提交为准。

## 6. 其他注意到的小问题

1. **授权口径**：三份 `list.md` 各有 13 处类群插图用 **CC BY-NC-SA**（如 `assets/images/mastotermitidae.jpg`；每份共 27 张插图），而数据集是 CC BY 4.0。
