# 世界名录对照（Blattodea Species File）操作说明

> 半自动对照：脚本自动匹配 → 人工复核工作表 → 导出小 JSON → 站点只在**人工核对过**时打「已核对」徽章。
> Semi-automatic cross-check against the Blattodea Species File: auto-match, human review, small JSON, honest badges.
> Verificación semiautomática con el catálogo mundial Blattodea Species File.

本目录与 `_data/bsf_links.json` 全部由 `.github/workflows/build_bsf_links.py` 生成；除本说明和
`导入模板.csv` 外，请勿手工编辑（人工意见只通过「工作表 + `--import`」回流）。

---

## 1. BSF 是什么

- **Blattodea Species File（BSF）**：<https://cockroach.speciesfile.org> —— 蜚蠊目（含**白蚁**，即原等翅目
  Isoptera Species File 已并入）的世界名录，由 Blattodea Working Group 维护，是白蚁分类的权威在线名录之一。
- 前台是 **TaxonPages**（Vite 单页应用，**MIT** 许可），后端是 **TaxonWorks**（同样开源，MIT）。
  站点没有稳定公开 API；但它的数据来自 TaxonWorks 的公共只读项目（project 48），
  且 **OTU 深链 `/otus/<OTU_ID>/overview` 是稳定的、服务端预渲染的**：页面里有学名、命名法、文献、
  模式标本、下阶元与异名统计。
- 我们只用三样东西：**OTU 编号**、**BSF 的拉丁名标签**（含命名人年份）、**深链 URL**。
  不镜像它的正文、图片、分布描述——正文永远留在 BSF 站点上。

### 为什么必须「半自动」

1. 没有承诺 SLA 的公开 API。脚本用的是 BSF 前端 bundle 里公开的只读 `project_token`，
   **随时可能失效、改路径、限流**——所以它只能当"辅助匹配"，不能进构建的关键路径。
2. 自动匹配本质是字符串判定，**属级归并、异名关系、亚种抬降**都需要人看一眼；
   如果把自动结果当成事实渲染出去，就是用机器猜测污染一个分类学名录。
3. 因此：自动匹配只产出"候选 + 状态"，**站点上只有通过复核（`verified: true`）的条目才显示「已核对」**，
   其余诚实标注「自动匹配待核对」。

### 工作表列

`latin, zh, family_latin, family_zh, bsf_status, bsf_label, bsf_valid_label, bsf_otu, bsf_url,
auto_rule, check_status, notes, reviewer`

- `latin / zh / family_*`：来自 `_species/*.md`，由脚本填，**不要改**（改了就对不上 JSON）。
- `bsf_status`：`valid` / `synonym` / `ambiguous` / `missing` / `error`，或空（尚未抓取）。
- `bsf_label`：BSF 返回的原始标签；异名行形如
  `异名 作者, 年 now 接受名 作者, 年`。
- `bsf_valid_label`：仅 `synonym` 行有值——BSF 认定的接受名。
- `bsf_otu` / `bsf_url`：OTU 编号与深链。**`synonym` 行的 URL 指向接受名那条 OTU**（BSF 把异名挂在接受名下面）。
- `auto_rule`：`exact`（精确命中）/ `manual`（人工录入）/ 空（未命中）。
- `check_status`：**你唯一必须动的列**：
  - `待核对`（默认，自动匹配有结论，等人看）
  - `已核对`（人确认过 → JSON 里 `verified: true` → 站点显示「已核对」）
  - `待补录`（`missing`/`error` 的默认值：BSF 没匹配上或没抓到，等人手工填 `bsf_otu`）
- `notes`：说明。脚本会为 `ambiguous` 行预填候选（`候选：OTU 123 …；OTU 456 …`），可自由改写。
- `reviewer`：复核人署名（可选）。**只保存在工作表里**，不写进 `bsf_links.json`
  （JSON 条目固定 9 个字段：`status / otu / label / valid_otu / valid_label / url / match / verified / notes`）。

## 3. 自动匹配规则（严格，绝不模糊接受）

对 `_species/*.md` 的每一条 `latin`，查询 TaxonWorks
`GET /otus/autocomplete?term=<name>&project_token=…`，然后：

| 判定 | 条件 | 写进 JSON |
| --- | --- | --- |
| `valid` | 某候选 `id == otu_valid_id`，且其拉丁名**前 N 个词**（N = 本站名的词数）与本站名**逐词**相等（大小写不敏感）；并且**去重后恰好只有 1 个不同 OTU**，没有同时命中异名行 | `otu` = 该 OTU，`label` = BSF 标签 |
| `synonym` | 某候选的拉丁名前 N 词与本站名相等，但 `id != otu_valid_id`，且标签含 `" now "` → 本站名是**异名**；恰好 1 个不同接受 OTU 才算通过 | `otu`/`valid_otu` = 接受名 OTU，`valid_label` = `" now "` 之后的接受名 |
| `ambiguous` | 有候选但结论不唯一：多个不同有效 OTU、`valid` 与 `synonym` 同时命中、或**只有模糊候选**（例如查 `Termes flavipes` 只回来 `Reticulitermes flavipes`） | `otu` = `null`（**不做断言**），候选写进 `notes` |
| `missing` | 一个候选都没有 | `otu` = `null` |
| `error` | 重试 4 次仍 429/5xx/超时 | `otu` = `null`，下次运行自动重查 |

补充约定（都是"宁可漏，不可错"）：

- **本站名是种（2 词），BSF 标签却是三名法**（第 3 词是小写种加词）→ 那是亚种 OTU，**不认领**。
- **本站名是亚种（3 词）** 时，要求 BSF 标签前 3 词逐词相等；BSF 若只到种级，则不算命中。
- 标签形如 `Genus (Subgenus) species …`（属名后带亚属括号）时，只剥离**第 2 个位置的括号**再比对，
  并在 `notes` 注明「BSF 标签含亚属括号」。作者的括号出现在名称之后，不受影响。
- 完全相同的候选行会去重；`✓`（`id == otu_valid_id`）与 `now` 语义分别对应"有效"与"异名"。
- 判定只用**字符串精确相等**，不做编辑距离、不做属级合并，绝不"猜"。

> 因此 `ambiguous` 里的"仅模糊候选"其实是**很可能没收录**的名称——仍然单独标出来，是为了让你一眼否掉，
> 而不是让它混进 `missing` 假装"查过了没有"。

## 4. 复核工作表怎么用

1. 用 Excel 打开 `_tools/bsf对照/工作表.csv`（UTF-8 BOM，中文不乱码）。
2. 建议先按 `bsf_status` 排序：`synonym` → `ambiguous` → `待补录(missing/error)` → `valid` 抽查。
3. **点开 `bsf_url` 核对**：页面标题的学名是否就是本站名（`valid`），或本站名是否在"异名"区（`synonym`）。
4. 判定：
   - 对 → `check_status` 改成 `已核对`，填 `reviewer`；
   - 错/需要保留原样 → 就留在 `待核对`（不要删行，不要清空 `bsf_otu`）；
   - BSF 真没有 → `待补录`，若你在 BSF 里找到了正确 OTU，把编号填进 `bsf_otu`（或整段 URL 填进 `bsf_url`）。
5. 保存为 **CSV UTF-8**（Excel 另存时选「CSV UTF-8（逗号分隔）」；不要存成 xlsx）。

> 脚本永远不会删行；重排工作表时会保留 `check_status`、`notes`、`reviewer`，
> `待补录` 行里你手填的 `bsf_otu` / `bsf_url` 也会保留。

## 5. 导入回收（`--import`）

```powershell
$env:PYTHONIOENCODING='utf-8'
python .github/workflows/build_bsf_links.py --import _tools/bsf对照/工作表.csv
```

`--import` 会：

- `check_status = 已核对` → JSON 条目 `verified = true`，`notes` 写进 JSON，`reviewer` 留在工作表；
  若你改了 `bsf_otu`，**以人工值为准**并打印「ID 变更 旧 → 新」（不会静默覆盖）。
  若该行标了 `已核对` 却没有任何 OTU（工作表 `bsf_otu`/`bsf_url` 都空、JSON 里也没有），**不会采信**，会列进报告。
- `check_status = 待补录` 且填了 `bsf_otu`（或含 `/otus/123` 的 URL）→ 采信该 OTU，`match = manual`；
  但 **`verified` 仍为 `false`**，请把该行改成 `已核对` 再导入一次，站点才会出现「已核对」徽章。
- 其它行只回填 `notes` / `reviewer`，**不改结论**。
- 行里的 `latin` 不在 `_species` 中（改名、错字、旧名）→ **列出来告诉你**，不写入 JSON，也不静默丢弃。
- 结束后自动重写 `_data/bsf_links.json` 与工作表（排序、缩进、换行都固定，重跑零改动的部分）。

## 6. 站点如何渲染（给模板维护者）

`_data/bsf_links.json` 结构：

```json
{
  "meta": {
    "generated": "2026-10-28T16:06:44Z",
    "source": "Blattodea Species File (cockroach.speciesfile.org)",
    "api": "https://sfg.taxonworks.org/api/v1",
    "citation": "Blattodea Working Group. Blattodea Species File Online. https://cockroach.speciesfile.org",
    "fetched": 3068,
    "counts": {"total": 3068, "valid": 0, "synonym": 0, "ambiguous": 0, "missing": 0, "error": 0},
    "pending": 0,
    "spot_check": {"checked": 20, "passed": 20, "sample": []},
    "review": "semi-automatic; see _tools/bsf对照/操作说明.md"
  },
  "name_map": {
    "Coptotermes formosanus": {
      "status": "valid", "otu": 83152, "label": "Coptotermes formosanus Shiraki, 1909",
      "valid_otu": 83152, "valid_label": null,
      "url": "https://cockroach.speciesfile.org/otus/83152/overview",
      "match": "exact", "verified": false, "notes": ""
    }
  }
}
```

- 键就是 `page.latin`（与 `_species` 的 `latin` 完全一致）。
- **只有 `verified: true` 才能显示「已核对」**；其余一律「自动匹配待核对」。
- `ambiguous` / `missing` / 未抓取（键不存在）→ `otu` 为 `null`，**不要渲染成链接**，最多提示"BSF 未匹配"。

## 7. 抓取礼貌与限速（请勿调快）

- **全局 ≤2 请求/秒**：所有线程共享一条"发车时刻"队列，请求起始间隔 ≥0.5 s，最多 4 个在途。
- **只读**：只调 `/otus/autocomplete` 与前台 `/otus/<id>/overview` 两个端点，从不 POST/PUT。
- **UA 带项目地址**：`isoptera-checklist-bsf/1.0 (+<本站 URL>)`，出问题对方能找到我们。
- **429/5xx/超时**：指数退避（1→2→4→8→16 s，尊重 `Retry-After`），最多 4 次；
  **连续 5 次失败**、或 token 被拒（401/403）→ **立即干净停止**，保留已抓到的结果，并在 `meta.aborted` 写明原因。
- **缓存就是 committed 的 JSON**：已有结论的名称重跑不会重查，一次全量抓取约 **26 分钟 / ~3100 次请求**，
  之后增量刷新通常是秒级。请不要为了"刷一下"而 `--refresh` 全量重跑。
- **别把联网抓取放进 CI**：`pages.yml` 里只该跑 `--check`（纯离线校验）。抓取是维护者手动、低频的动作。

## 8. 常用命令

```powershell
$env:PYTHONIOENCODING='utf-8'

# 只统计（不联网、不写文件）
python .github/workflows/build_bsf_links.py

# 首次全量 / 续跑（断点续传；中断后原样再跑即可）
python .github/workflows/build_bsf_links.py --write

# 分批跑，避免长时间占用（每次 200 个新名称）
python .github/workflows/build_bsf_links.py --write --limit 200

# 限时跑（例如只给它 10 分钟）
python .github/workflows/build_bsf_links.py --write --budget 600

# 完全不联网，只用缓存重排 JSON/工作表
python .github/workflows/build_bsf_links.py --no-api --write

# 回收人工复核结果（同时重写 JSON 与工作表）
python .github/workflows/build_bsf_links.py --import _tools/bsf对照/工作表.csv

# 产物一致性校验（离线，CI 用；不一致退出码 1）
python .github/workflows/build_bsf_links.py --check

# 全部重查（已 verified 的条目保留，不会冲掉人工结论）
python .github/workflows/build_bsf_links.py --write --refresh

# 抽查 OTU 深链是否还能打开（默认 20 个，随机种子固定 → 可复现）
python .github/workflows/build_bsf_links.py --write --spot-check 20
```

### 刷新流程（建议每季度或 BSF 大改版后）

1. `--write`（增量，补上新增物种；已有结论复用缓存）。
2. 若怀疑 BSF 有较大分类变动：`--write --refresh`（全新查一遍，人工 `verified` 条目会保留，
   若确实变了，脚本会在 `--import` 时报告 ID 变更，由人决定）。
3. 看 `meta.spot_check`：`passed < checked` 说明深链失效或 API 变了，先修脚本再发版。
4. `--check` 通过后再提交 `_data/bsf_links.json` 与工作表。

## 9. 已知限制 / 注意

- **autocomplete 覆盖有限**：它按标签模糊匹配，并不保证返回项目里所有同名 OTU。
  某些真实异名（例如 `Termes flavipes` → `Reticulitermes flavipes`）查不到，会被判成 `ambiguous` 或 `missing`。
  这是**保守**的方向：宁可漏，不错认。看到 `ambiguous` 里只有 `仅模糊候选` 的行，基本可以判为"BSF 未收录该名"。
- **同名异物（homonym）**：若两个不同 OTU 都叫这个名字，脚本判 `ambiguous`，交给人。
- **亚种**：BSF 的亚种覆盖不完整；本站 63 个亚种里，未在 BSF 建亚种 OTU 的会落到 `ambiguous/missing`。
- **`otu_valid_id` 为空**的候选一律不认领（无法判断有效/异名）。
- **token 失效**：`meta.aborted` 里会出现「API 拒绝了 token」。此时去 BSF 前端 bundle
  （`https://cockroach.speciesfile.org/assets/index-*.js`）里搜 `project_token` 换掉 `PROJECT_TOKEN` 常量，
  再重跑；脚本不会因此产出错误数据（失败一律 `error`，不猜）。
- **抽查只证明"链接能打开、名字在页面上"**，不证明分类学正确；正确性靠人。
- **法律/伦理**：TaxonWorks / TaxonPages 是 MIT 软件；BSF 的数据内容版权归 Blattodea Working Group。
  我们**只存**拉丁名、命名人年份标签、OTU 编号与链接，不镜像正文；引用请保留 `meta.citation`
  （Blattodea Working Group. Blattodea Species File Online. <https://cockroach.speciesfile.org>）。
