# S0455 actions/jekyll-build-pages

只读了仓库主分支的四个文件（action.yml / entrypoint.sh / Dockerfile / Gemfile），没有读更深实现；镜像标签 v1.0.13 与线上现用一致。Dockerfile 为 ruby:3.3-slim + bundle install，入口 ENTRYPOINT ["/entrypoint.sh"]。

## 摘录（逐字，不得改写）

- **entrypoint.sh, L14-15**：

  > SOURCE_DIRECTORY=${GITHUB_WORKSPACE}/$INPUT_SOURCE
  > DESTINATION_DIRECTORY=${GITHUB_WORKSPACE}/$INPUT_DESTINATION

  说明：支撑：构建的 source/destination 都以 GITHUB_WORKSPACE 为根拼出来 → 用 docker run 手动复刻时必须把仓库根挂进容器并设 GITHUB_WORKSPACE

- **entrypoint.sh, L56**：

  > build_output="$($GITHUB_PAGES_BIN build "$VERBOSE" "$FUTURE" --source "$SOURCE_DIRECTORY" --destination "$DESTINATION_DIRECTORY")"

  说明：支撑：容器里真正执行的是 github-pages build（不是裸 jekyll），--source/--destination 都是绝对路径；这是三语切片必须自己 docker run 同一镜像的原因

- **entrypoint.sh, L24-28**：

  > export JEKYLL_ENV="production"
  > export JEKYLL_GITHUB_TOKEN=$INPUT_TOKEN
  > export PAGES_REPO_NWO=$GITHUB_REPOSITORY
  > export JEKYLL_BUILD_REVISION=$INPUT_BUILD_REVISION
  > export PAGES_API_URL=$GITHUB_API_URL

  说明：支撑：Pages 工具链给插件注入的环境变量清单；手动 docker run 时要照样传入，否则 jekyll-seo-tag/sitemap 的输出会与线上不同

- **action.yml, L5-12**：

  > source:
  >     description: 'Directory where the source files reside.'
  >     required: false
  >     default: ./
  >   destination:
  >     description: 'Output directory of the build. Although it can be nested inside the source, it cannot be the same as the source directory.'
  >     required: false
  >     default: ./_site

  说明：支撑：source/destination 是两个可传的输入，默认 ./ 与 ./_site——三语切片正是靠这两个输入各指一份目录

- **action.yml, L29-31**：

  > runs:
  >   using: 'docker'
  >   image: 'docker://ghcr.io/actions/jekyll-build-pages:v1.0.13'

  说明：支撑：action 是 docker action，镜像标签钉在 v1.0.13；手动 docker run 必须用同一个镜像，才能与线上插件集一致
