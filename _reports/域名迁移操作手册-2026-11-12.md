## 1. 第一步：GitHub 仓库设置里填域名（务必在 DNS 之前）

路径：仓库 **Settings → Code, planning, and automation → Pages → Custom domain**，
填 `termite-extant-isoptera.org`，点 **Save**（不要填 `https://`、不要带尾斜杠）。

顺序不能反。官方原文：

> Make sure you add your custom domain to your GitHub Pages site before configuring your custom domain with your DNS provider. Configuring your custom domain with your DNS provider without adding your custom domain to GitHub could result in someone else being able to host a site on one of your subdomains. <!-- src:S0431 -->

**这一步不会产生 CNAME 文件**，也不要手工补：本站用自定义 GitHub Actions 工作流发布，
官方原文「If you are publishing from a custom GitHub Actions workflow, no `CNAME` file is created, and any existing `CNAME` file is ignored and is not required.」 <!-- src:S0431 -->
网上大量教程让你「加个 CNAME 文件」，对本站的发布方式是错的。

（可选但推荐）更稳的做法是先做**域名验证**：同页面的 **Verify domain** 给出一串
`_github-pages-challenge-bennetgreen-bilibili=<token>`，先在 Cloudflare 建成 **TXT** 记录，
验证通过后再填 Custom domain。验证过之后，其他 GitHub 账号就无法把这个域名挂到自己仓库上。 <!-- src:S0431 -->

## 2. 第二步：Cloudflare 建记录

Cloudflare → 选中 zone `termite-extant-isoptera.org` → **DNS → Records**。当前 zone 是空的
（2026-11-12 实测 apex 无任何 A/AAAA/TXT，www NXDOMAIN），所以是「新建」而不是「改」。

**全部设成 DNS only（灰色云朵）**。Cloudflare 新建记录时默认是 Proxied（橙色云朵），必须手动关掉。
橙云会让 Cloudflare 用自己的证书与 GitHub 抢 TLS，常见后果是 526/重定向循环，首日不要开。

### 2.1 apex（`@`）

| 类型 | 名称 | 内容 | 代理 |
| --- | --- | --- | --- |
| A | `@` | `185.199.108.153` | DNS only |
| A | `@` | `185.199.109.153` | DNS only |
| A | `@` | `185.199.110.153` | DNS only |
| A | `@` | `185.199.111.153` | DNS only |
| AAAA | `@` | `2606:50c0:8000::153` | DNS only |
| AAAA | `@` | `2606:50c0:8001::153` | DNS only |
| AAAA | `@` | `2606:50c0:8002::153` | DNS only |
| AAAA | `@` | `2606:50c0:8003::153` | DNS only |

上表 8 条 IPv4/IPv6 地址照抄 GitHub 官方表格（「§ DNS records for your custom domain」）。 <!-- src:S0431 -->

### 2.2 www

| 类型 | 名称 | 内容 | 代理 |
| --- | --- | --- | --- |
| CNAME | `www` | `bennetgreen-bilibili.github.io` | DNS only |

CNAME 指向 `<user>.github.io`，**不带仓库名**；apex 与 www 之间的 301 由 GitHub 自动做，
配置 `www` 之后访问 `www.termite-extant-isoptera.org` 会 301 到 apex。 <!-- src:S0431 -->
站点在 GSC/分享里统一用不带 www 的地址，别把 www 设成 GitHub 的 Custom domain，否则方向反过来。

### 2.3 两个「别踩」

1. **apex 上不要有任何其它记录**（含 Cloudflare 自动生成的占位 A 记录、`A @ 192.0.2.1` 之类）。
   官方原文：「Any additional `A`, `AAAA`, `ALIAS`, `ANAME` records with the `@` host, or `CNAME` records pointing to your `www` subdomain or other custom subdomain that you would like to use with GitHub Pages may prevent the HTTPS certificate from generating.」 <!-- src:S0433 -->
2. **不要建通配符 `*` 记录**，会带来子域被接管的风险；GitHub 也不许一个域名同时挂 apex 和别的子域（www 除外）。 <!-- src:S0432 -->

## 3. 第三步：验证 DNS 已生效

Windows 上 `dig` 没有，用 PowerShell（`Resolve-DnsName`）：

```powershell
Resolve-DnsName termite-extant-isoptera.org -Type A
Resolve-DnsName termite-extant-isoptera.org -Type AAAA
Resolve-DnsName www.termite-extant-isoptera.org -Type CNAME
# 用公共 DNS 复核，排除本地缓存：
Resolve-DnsName termite-extant-isoptera.org -Type A -Server 1.1.1.1
Resolve-DnsName termite-extant-isoptera.org -Type A -Server 8.8.8.8
```

期望：A 四条 185.199.108–111.153、AAAA 四条 `2606:50c0:800x::153`、www 的 CNAME 落在
`bennetgreen-bilibili.github.io`。Cloudflare 改了就在自家 NS 上立刻生效，不需要等 24 小时传播，
`1.1.1.1` / `8.8.8.8` 通常几十秒跟上。

## 4. 第四步：等证书，然后开 Enforce HTTPS

回到 **Settings → Pages**，看 Custom domain 右侧是否出现 ✓。出现前：

- 签发可能要几分钟到一小时；GitHub 会自动向 Let's Encrypt 申请证书。 <!-- src:S0432 -->
- 几分钟后还没好，就点 **Remove** 再重新填一次域名并 **Save**，这会取消并重启签发流程。 <!-- src:S0433 -->
- 只有在 ✓ 出现后，**Enforce HTTPS** 复选框才会变成可勾选状态（官方：可能要等最多 24 小时）。 <!-- src:S0431 -->
- 如果 Cloudflare 那边建过 CAA 记录，必须有一条 `letsencrypt.org`，否则证书签不出来。 <!-- src:S0432 -->

## 5. 第五步：部署新配置（顺序很重要）

**等 §4 的 ✓ 出现之后再 `git push`。** 原因：新 `_config.yml` 把 `baseurl` 清空了，
全站资源引用会变成 `https://termite-extant-isoptera.org/assets/…` 这样的根路径绝对地址；
如果域名还没接管访问，旧的 `bennetgreen-bilibili.github.io/…-Comparison-List.md/` 地址上的
CSS / JS / 搜索索引会 404，站点会先「白」一段时间。

推送后 Actions 会自动构建并部署（`.github/workflows/pages.yml`，其中 verify job 的
`BASE` 已改成新域名，部署完会自检 15 个路径）。等 workflow 绿了再做 §6。

1. 新增属性：**域名属性** `termite-extant-isoptera.org`（DNS 验证，在 Cloudflare 加一条 `_github-pages-challenge` 之前的 TXT 或 GSC 给的 TXT），或 **URL 前缀** `https://termite-extant-isoptera.org/`。
2. 提交 `https://termite-extant-isoptera.org/sitemap.xml`（3,000+ 条；`sitemap.txt` 是给别的引擎的备用格式）。
3. 旧属性 `https://bennetgreen-bilibili.github.io/-Extant-…-Comparison-List.md/` 用 **设置 → 地址更改（Change of address）** 指向新域名；只有两个属性都验证过才能用。
4. 之前「sitemap 抓不到」的病根是站点在项目子路径、域名根没有 robots.txt；现在根上有了，重新提交后再看覆盖率报告。

## 8. 回滚

任何一步出问题都能退回去，代价很小：

1. GitHub **Settings → Pages → Custom domain → Remove**（这会让旧项目地址恢复自己服务自己）。
2. Cloudflare 删掉 §2 的 9 条记录。
3. 把 `_config.yml` 三行还原成旧值，重跑 `_tools/regen_all.sh` 的 12 步。
